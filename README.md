# cbam-watch

EU 탄소국경조정제도(CBAM)의 규제 동향을 원문과 함께 정리해 보여 주는 사이트의 저장소입니다.

- 사이트: https://ansh91655-a.github.io/cbam-watch/
- 사이트의 정리와 번역은 자동으로 수집하고 작성한 것이며, 게시 전에 사람이 검수하지 않습니다. 정확한 내용은 반드시 원문에서 확인하세요. 법률 자문이 아닙니다.

## 폴더

| 폴더 | 내용 |
| --- | --- |
| `sources/registry.json` | 출처 대장. 어디를 어떤 방법으로 보는지 적혀 있다 |
| `sources/labels.json` | 화면에 적는 출처의 국문 이름(대장의 이름은 운영에 쓰는 이름이다) |
| `collected/` | 수집 결과. `feed/`(그날 새로 보인 것), `state/`(이미 본 것의 열쇠), `pages/`(EU 공식 화면의 글), `status.json`(출처별 확인 결과), `archive/`(지난 소식을 한꺼번에 모은 것. 아래 '지난 소식 채우기' 참조. `archive/pdfs/`에는 법령의 관보 PDF를 둔다) |
| `originals/` | EU 집행위원회 문서의 사본(`files/<문서 id>/<해시>/<원래 파일 이름>`), 뽑아 낸 본문(`text/`), 판 사이의 비교 결과(`diffs/`), 대장(`state.json`) `units/`에는 PDF에 적힌 짜임에서 읽은 뜻 단위(제목, 문단, 목록 항목, 표의 칸, 각주)를 둔다(`tools/pdfko/units.py`). |
| `assets/fonts/` | 국문 PDF에 번역을 찍는 글꼴(Pretendard. OFL 1.1이고 허락글이 함께 있다) |
| `data/` | 사이트에 게시한 데이터. 소식(`items.json`), 주제 목록(`topics.json`), 인증서 가격(`prices.json`, 프로그램이 가격표에서 만든다), 일정(`events.json`), 주간 요약(`digests.json`), 용어집(`terms.json`), 하나로 묶은 소식의 기록(`merged.json`), 규제별 진행 상황(`regulations.json`), 품목 코드 조회의 목록(`cn.json`), 법령에서 옮겨 온 참고 자료(`factor.json`, `duties.json`, `calc.json`, `calc-goods.json`), CBAM 해설서의 글(`handbook.json`), 역할별 준비 목록(`prepare.json`), 규정 원문과 안내 문서의 국문 번역(`laws-ko/`, 문서마다 한 파일) |
| `reports/` | 보고 실행이 올리는 그날과 그 주의 보고 파일. 알림의 근거다 |
| `language/` | 국문 표기 기준(용어집 `glossary.json`), 번역 실행들이 정해 둔 낱말(`translation-terms.json`), 번역을 지운 까닭(`translation-reviews.json`), 검수의 결과(`translation-checks.json`) |
| `site/` | 공개 사이트의 화면 파일. 화면마다 모듈 하나(`js/views/`), 그림과 달력 같은 부품(`js/ui/`), 디자인 값(`css/tokens.css`)과 색 변형(`css/themes.css`), 파비콘과 공유 미리보기 그림과 라이선스 고지(`assets/`). 아래 '사이트의 디자인' 참조 |
| `console/` | 운영 화면의 파일. 올릴 폴더는 `python3 -m tools.publish.build_console`이 만든다(사이트의 화면 도우미 `dom.js`, `format.js`를 복사해 넣는다). 사이트 쪽 도우미가 바뀌어 콘솔의 모듈이 맞물리지 않게 되면 '도구 검사'가 잡는다(`tools/dev/modlink.mjs`) |
| `tools/` | 정해진 일을 하는 프로그램. 아래 표 참조 |
| `tests/` | 도구의 자동 시험. 도구나 시험, 그리고 시험이 읽는 것(워크플로, 화면의 코드, 운영 콘솔, 설정과 대장, 사이트에 싣는 자료, 받아 둔 원문의 글과 단위)이 바뀌면 돈다. 번역 묶음(`data/laws-ko`)마다는 돌지 않고 실행이 끝났다는 표가 바뀔 때 한 번 돈다(`.github/workflows/tests.yml`. 무엇을 넣고 뺐는지는 `tests/test_triggers.py`가 본다: 새 시험이 화면의 코드나 설정을 새로 읽으면 그 파일이 경로에 들어 있어야 한다) |

### tools

| 묶음 | 하는 일 |
| --- | --- |
| `tools/common` | 웹에서 받기, HTML에서 글 뽑기, JSON 읽고 쓰기, 사이트 주소와 배포하는 곳 읽기(`siteinfo`: 주소는 `site/site.config.json`의 `url`, 사이트만 싣는 저장소를 따로 둘 때의 이름은 `deploy.json`의 `siteRepo`) |
| `tools/collect` | 출처 화면에서 새 항목 찾기(`extract`), JSON 목록 보기(`jsonwatch`), 그날 목록 만들기(`feed`), 실행(`run`). 이용 조건을 밝힌 공공기관 게시글의 본문 받기(`articles`: 수집 기록의 그 줄에 받은 글의 경로를 적어 예약 실행이 본문으로 요약하게 한다. 본문 자리 찾기는 `article_text`) |
| `tools/originals` | 문서 링크 찾기(`discover`), 받을 차례 정하기(`queue`), 판 남기기와 비교(`versions`, `diff`), 본문 뽑기(`textify`), 실행(`run`), 자동으로 받지 못하는 문서를 사람이 받아 넣기(`supply`. 아래 '자동으로 받지 못하는 문서') |
| `tools/check` | 국문 글 검사: 용어(`term_check`, `term_lookup`), 표기(`style_check`), 수치와 날짜 대조(`fact_check`), 원문 발췌 확인(`excerpt_check`) |
| `tools/prices` | 인증서 가격표 읽기: 적용 기간 읽기(`periods`), 표의 행 읽기(`parse`), 가격 자료 만들기(`run`) |
| `tools/publish` | 게시 데이터에 더하기(`add_items`, `add_digest`), 요약 내리기(`withdraw`), 같은 일을 두 번 실은 소식을 하나로 묶기(`merge`: 묶인 소식은 `data/merged.json`에 남고, 옛 주소는 남긴 소식으로 넘어간다), 주제 목록(`topics`), 사이트와 운영 화면의 폴더 만들기(`build_site`, `build_console`). 사이트 폴더를 만들 때 규제 자료의 공개용 사본(`regulations`), 소식의 미리보기 그림 주소(`thumbs`), 구독 피드 `feed.xml`과 `rules.xml`(`feed`. 새 소식 받아 보기를 열어 둔 동안에만), 화면에서 바로 보는 문서 사본 `files/`(`derive`)도 함께 만든다. 규제 자료 고치기(`rule_edit`), 제목만 옮겨 실은 소식의 요약을 원문을 읽고 다시 쓴 것으로 바꾸기(`revise`)도 여기에 있다. 소식·의무 일정·용어집에 적힌 법령과 조문을 규정 원문으로 잇기(`crossrefs`), 부문별 모아 보기의 자료 만들기(`sectors`), 품목 한 장 보기가 잇는 근거 조문과 해설서의 절(`item_sheet`), 글 속 용어 풀이의 자료(`gloss`), CBAM 해설서의 검사와 공개용 사본(`handbook`, 그림의 꼴은 `handbook_figures`)도 사이트를 만들 때 함께 돈다 |
| `tools/notify` | 보고 파일에서 알릴 것을 골라 '운영 보고' 이슈에 적기(`reports`, `messages`, `github`, `run`) |
| `tools/run` | 예약 실행이 쓰는 보조 도구: 후보 고르기, 검증 대기 고르기, 보류된 초안 가운데 다시 쓸 것 고르기(`holds_to_fix`: 글을 고치면 풀리는 사유)와 그대로 다시 검증에 낼 것의 사본 만들기(`holds_to_recheck`: 원문을 열지 못한 것. 두 번까지, 규칙은 `rechecks.py`), 제목만 옮긴 초안의 원문 제목을 수집 기록에서 찾기(`feed_title`), 원문 발췌 자르기, 상태 점검(`health`, 규제 자료는 `rules_health`, 품목 코드 목록과 기관별 입장 비교표는 `cn_health`), 하루와 한 주의 요약, 보고 파일 만들기(`write_report`) |
| `tools/archive` | 공식 기록을 모으는 프로그램. 지난 소식을 한꺼번에 채울 때 손으로 돌리고, 규제 진행 상황에 쓰는 기록은 평일마다 자동으로 돈다: 출처별 모으기(`ecnews`, `newsletter`, `eurlex`, `cellar`, `docs`, `oeil`, `hys`, `presscorner`, `council`, `govuk`, `ukleg`, `fedreg`, `boards`)와 실행(`crawl`), 새 자료를 그날의 후보로 넘기기(`tofeed`), 화면의 짜임 살펴보기(`dump`), 싣기 전 검사(`gate`), 싣기(`publish`). 법령의 본문 받아 두기(`acts`: 부속서가 규칙의 글인 법령은 부속서까지 온전히), 법령의 앞선 판 남기기(`earlier`: 처음 관보에 실린 글과 지난 통합본. 달라진 곳 보기가 견줄 글), 법령의 관보 PDF 받아 두기(`actpdf`: PDF 나란히 보기가 쓰는 원문. 날마다의 수집이 받아 두지 않은 것만 받는다), EU 조약의 조문과 절차를 정한 문서 받아 두기(`primary`: 입법 절차 화면의 근거. 조약은 거의 바뀌지 않으므로 손으로만 돌린다: 워크플로 '소급 수집'에서 `steps = eu-primary`) |
| `tools/cn` | 품목 코드 조회의 목록을 법령 원문에서 만드는 프로그램: 부속서의 품목 표 읽기(`annex`), `data/cn.json` 만들기(`build`), 통합본의 판 다루기(`versions`), 새 통합본이 나오면 본문을 받아 목록을 다시 만들기(`refresh`, 평일 수집이 돌린다. 부속서를 제대로 읽었는지의 확인에 걸리면 아무것도 바꾸지 않고 사유를 `collected/cn/refresh.json`에 남긴다). 원문은 `collected/archive/pages/eu-fulltext/`에 있다. 코드를 견주는 셈은 사이트의 `site/js/cn/match.js`, 개정안의 단계에 따라 안내의 말을 바꾸는 기준은 `site/js/cn/stage.js`에 있다 |
| `tools/thumbs` | 소식 카드의 미리보기 그림을 만드는 프로그램: 만들 것 고르기(`plan`), 원문 화면의 제목 부분 찍기(`shots.mjs`), 법령 PDF의 첫 장 받기(`pdfcover`), 줄여서 싣기(`finish`). 재이용이 허용된 공식 출처만 다루고, 화면을 여는 브라우저는 자동으로 여는 것임을 숨기지 않는다 |
| `tools/common` | 여러 프로그램이 함께 쓰는 것: 웹에서 받기(`net`), robots.txt 지키기(`robots`), 화면의 글 뽑기(`htmltext`), JSON 읽고 쓰기(`jsonio`), 사이트 주소와 배포 저장소(`siteinfo`) |
| `tools/laws` | 규정 원문 화면의 자료를 만드는 프로그램: 받아 둔 법령의 글을 조와 문단으로 나누기(`segment`), 안내 문서를 PDF의 뜻 단위에서 조각으로 만들기(`unit_segment`), 꼬리표가 없는 PDF의 글을 쪽·문단·절로 나누기(`pdf_pages`, `pdf_blocks`, `guide_segment`), 나누는 방식이 바뀐 문단에 옛 번역 옮겨 붙이기(`carry`), 싣는 문서의 목록(`catalog`, `guides`), 문서와 번역을 함께 읽기(`corpus`), 번역 자료 읽고 쓰기(`store`), 번역 검사(`check`, 용어는 `terms`), 전문용어의 영문 병기(`gloss`), 사이트 자료 만들기(`build`), 번역 실행마다 맡는 갈래(`plan`), 다음에 옮길 문단 고르기(`todo`)와 옮긴 것 넣기(`apply`, 끝맺음 맞추기는 `finish`), 번역 실행들이 정해 둔 낱말(`wording`), 검수(`verify`, 검수를 재려고 번역을 일부러 틀리게 바꾸는 `spoil`), 표본 검토(`review`), 모델 견주기 시험(`trial`), 진행 상황(`status`), 앞선 판과 견주기(`compare`)와 달라진 곳의 공개 자료(`revisions`), 같은 문장이 다르게 옮겨진 것 찾아 맞추기(`alike`). 아래 '규정 원문과 국문 번역' 참조 |
| `tools/pdfko` | PDF로 받은 문서를 다루는 프로그램: 낱말의 자리(`geometry`), 글자와 내용 조각 번호(`glyphs`), 구조 꼬리표(`tags`), 뜻 단위(`units`) 읽기와, 국문 PDF 만들기(단위를 글자에 잇기 `bind`, 자리 정하기 `layout`, 원문 글자 들어내기 `erase`, 글꼴 `fonts`, 찍기 `typeset`, 문서 하나 `build`, 사이트에 싣기 `site`). 꼬리표가 없는 PDF는 글을 맞추어 자리를 찾는다(`match`) |
| `tools/calc` | 인증서 비용 추정의 품목 자료를 법령의 표에서 만드는 프로그램: 받아 둔 표 읽기(`source`), 품목마다 기본값과 벤치마크를 짝지어 `data/calc-goods.json` 만들기(`build`) |
| `tools/sitecheck` | 만든 사이트를 브라우저로 열어 가로 넘침, 화면 오류, 접근성을 검사하는 프로그램(Node). 아래 '화면 점검' 참조 |
| `tools/art` | 사이트의 그림을 만드는 프로그램. 손으로 돌린다: 점 지도(`dotmap`, 뱃길은 `sealane`, 나라 경계 읽기는 `world`), 유리 면 위의 글자 대비 셈(`glass`), 아이콘(`icons`), 라이선스 고지(`notices`), 공유 미리보기 그림의 원본(`social.html`) |

자동으로 받는 것은 모두 `tools/common/net.py`를 거치고, 이 함수는 주소를 열기 전에 그 사이트의 robots.txt를 봅니다(`tools/common/robots.py`). 사이트가 자동 읽기를 막은 주소는 받지 않고, 막힌 주소는 `collected/robots.json`에 남아 그날의 상태 점검이 알립니다. 이 수집기의 이름(cbam-watch)을 적은 규칙과 함께 Claude의 수집기 이름을 적은 규칙도 따릅니다(받은 글을 Claude가 읽고 요약하기 때문입니다). 사이트가 확인 요청이나 접근 거부 화면을 내면 넘어서려 하지 않습니다. 주소 하나를 손으로 확인하려면 `python3 -m tools.common.robots <주소>`를 씁니다.

예약 실행(Claude)이 웹 화면을 직접 읽는 일은 최소로 둡니다. 예약 실행의 웹 읽기는 그 실행의 웹 검색 결과에 그대로 나온 주소만 사람의 확인 없이 열 수 있기 때문입니다(2026-11-12에 시험으로 확인. 저장소 파일이나 절차서에 적힌 주소, 열어 본 화면에 걸린 링크는 열리지 않습니다). 그래서 소식의 원문은 되도록 이 저장소의 자동 실행이 받아 둔 글에서 읽고(EU 기관의 화면과, 이용 조건을 밝힌 공공기관 게시글의 본문), 제목만 옮기는 소식은 수집 기록(`collected/feed/`)의 제목과 견주어 검증합니다. 출처 대장에서 `collector`가 `claude`인 출처만 예약 실행이 웹 읽기로 열며, 그 출처의 `find`에 적힌 검색어로 검색해 결과에 주소가 그대로 나올 때만 엽니다.

프로그램은 저장소 맨 위에서 `python3 -m tools.<묶음>.<이름>` 꼴로 돌립니다. 표준 라이브러리만 쓰고, PDF 본문을 뽑을 때만 `pdftotext`가 필요합니다. 시험은 `python3 -m unittest discover -s tests -t .`로 돌리고, 올리기 전에는 `sh tools/dev/check.sh`(자동 실행과 같은 꾸러미만 깐 깨끗한 환경에서 시험과 사이트 만들기)를 돌립니다. 자동 실행은 결과를 `sh tools/dev/push.sh`로 올립니다(올리기가 응답 없이 멈추면 끊고 세 번까지 다시 해 보고, 끝내 안 되면 그 실행이 실패로 남습니다).

## 규제별 진행 상황

사이트의 '규제' 화면은 `data/regulations.json` 하나로 그린다. 규제마다 지금의 단계, 현재 상황, 다음 단계, 연혁(사건마다 원문 주소)을 가진다.

- 연혁의 근거는 세 가지다. `stored`는 저장소에 받아 둔 공식 자료(`collected/archive/`의 공식 기록, 원문 대장이 받아 둔 문서의 글 `originals/text/`)와 맞는 사건이고 프로그램이 실제로 맞춰 본다. `web`은 자동으로 받을 수 없는 공식 화면을 읽고 확인한 사건, `press`는 언론 보도로만 아는 사건이다(화면에 '언론 보도'로 표시된다).
- 검사: `python -m tools.publish.regulations`(꼴, 높임말, 용어, 근거). 사이트를 만들 때는 꼴과 표기만 막고, 근거가 공식 기록과 달라진 것은 알리기만 한다(공식 기록은 날마다 바뀐다).
- 고치기: `python -m tools.publish.rule_edit`(연혁에 한 줄 더하기와 빼기, 연혁의 글만 고치기 `reword`, 단계와 설명 고치기, 새 규제 더하기). 고친 뒤 자료 전체를 검사하고, 걸리면 고치지 않는다.
- 준비 중이던 하위 법령이 관보에 실리면 `python -m tools.publish.rule_edit enact --id <규제> --celex <번호>`로 그 규제를 '시행 중인 하위 법령'으로 옮긴다(`tools/publish/rule_enact.py`). 묶음, 이름과 종류의 '(안)'·'(계획)', 공식 이름, 원문 링크, 관련 낱말, 목록에서의 자리를 한 번에 바꾼다. 법령 전문 화면은 공식 이름의 번호로 규제와 이어지므로, 이것을 하지 않으면 새 법령의 전문 화면에서 규제 화면으로 가는 길이 생기지 않는다. 단계와 연혁은 이어서 `set`, `add-event`로 고친다.
- 다음 일정의 출처: 다음 단계에 날짜(`nextDate`)가 있으면 일정 화면에도 실린다. 그 날짜의 출처는 `nextSource`(이름과 주소)이고, 없으면 규제의 첫 링크다. 언론 보도로만 아는 날짜는 첫 링크의 공식 문서에 적혀 있지 않으므로, 다음 단계의 글이나 일정 이름에 '보도'가 있으면 `nextSource`가 있어야 한다(없으면 검사에 걸린다. `rule_edit set --next-source … --next-link …`). 날짜를 바꾸면서 새 출처를 주지 않으면 옛 출처는 지워진다.
- 기관별 입장 비교표: 규제에 `positions`가 있으면 화면에 '기관별 입장 비교'가 실린다(지금은 하류제품 확대 개정안과 임시 탈탄소화 기금 규정안). 칸마다 저장소에 받아 둔 원문 글에서 근거를 대고(`contains`, 그 문서에 없는 조항은 `lacks`) 프로그램이 맞춰 본다. `python -m tools.publish.rule_edit positions --id <규제> --file <표 파일>`로 넣고, 공개용 사본에는 칸의 글만 실린다.
- 분석 글: 규제에 `analysis`가 있으면 '개요' 아래에 배경, 주요 내용, 쟁점과 정세, 실무에서 볼 점이 실린다(검사와 변환은 `tools/publish/analysis.py`, 화면은 `site/js/views/rules/analysis.js`). 문단마다 근거 자료를 가리켜야 하고, 모아 둔 공식 자료만 가리키는 문단은 그 안의 날짜와 수를 자료의 글과 프로그램이 대조한다. 언론 보도에 기댄 문단은 글에서 그렇다고 밝혀야 한다. 권유와 전망으로 읽히는 말('~할 필요가 있습니다', '~하는 것이 좋습니다', '지켜볼', '~것으로 보입니다')과 날이 지나면 틀리는 말은 검사에 걸린다(`analysis.py`의 `ADVICE`). 원문이 정한 사실과 그 결과만 적는다. `python -m tools.publish.rule_edit analysis --id <규제> --file <분석 파일>`로 넣고 `analysis-show`로 꺼낸다. 규제의 단계나 연혁이 달라지면 화면이 '분석을 쓴 뒤에 달라졌다'고 스스로 밝히고, 사흘이 지나도록 그대로면 상태 점검이 알린다. 근거로 쓰는 글은 워크플로 '소급 수집'으로 받아 둔다. `steps`에 `eu-acts`를 적으면 시행 중인 법령의 본문을, `eu-fulltext`를 적으면 심의 중인 제안의 본문과 부속서, EU 배출권거래제 지침 통합본, 유럽의회 입법 관측소의 문서별 요약을, `uk-legislation`을 적으면 영국 CBAM 법령의 온전한 글을, `eur-lex-docs`를 적으면 CBAM 규정과 이어진 문서(계류 중인 소송의 공고 포함)를 받는다. `eu-tables`를 적으면 법령 부속서의 값 표를 칸의 자리를 살려 받는다(인증서 비용 추정의 자료). 규제를 고칠 때 다른 규제의 근거가 받아 둔 글과 달라진 것은 알리기만 하고 막지 않으며(`rule_edit.blocking`), 그 어긋남은 상태 점검이 따로 알린다.
- 달라진 것 찾기: `python -m tools.run.rules_watch`가 모아 둔 공식 기록이 지난번에 본 뒤로 달라졌는지 알려 준다. 본 것은 `data/rules-seen.json`에 적는다.
- 상태 점검: `tools/run/rules_health.py`가 근거 어긋남, 지난 일정, 반영되지 않은 변화, 기록 갱신 누락을 일일 보고의 문제로 올린다.
- 세부 절차: 규제가 따르는 절차와 그 절차의 어느 단계에 와 있는지를 함께 적는다. 아래 '입법 절차와 세부 단계' 참조.
- 공식 기록을 읽지 못한 날: 사이트가 점검 중이거나 답이 끊겨도 모아 둔 목록은 줄어들지 않는다. 읽지 못한 것이 있는 실행은 앞의 목록에서 빠진 기록을 그대로 남기고(`tools/archive/store.py`의 `save_index`), EU 법령 데이터베이스의 연관 문서는 빠진 문서와 관계를 되살린다(`tools/archive/cellar.py`의 `restore`). 무엇을 읽지 못했는지는 `collected/archive/report/`에 남는다.

## 입법 절차와 세부 단계

'규제 > 입법 절차' 화면(`#procedure`, `#procedure-who.<기관>`, `#procedure-acts.<종류>`, `#procedure-<절차>.<단계>`)은 EU의 기관이 저마다 무엇을 하는지, 법령의 종류, 절차마다의 단계를 설명하고, 진행 중인 규제가 지금 어느 단계에 와 있는지를 한눈에 보여 준다. 규제 화면에는 같은 단계가 '세부 절차'로 실린다: 지나온 단계와 그 날짜, 지금 와 있는 단계, 남은 단계.

- 자료는 `data/procedures.json` 하나다: 기관(`institutions`), 법령의 종류(`acts`), 문서 번호 읽는 법(`codes`), 절차(`kinds`: 일반입법절차, 위임규정, 이행규정, 자체 재원 결정, 국제 협정, EEA 협정 편입, 영국의 법률과 하위 법령, WTO 분쟁 해결, EU 사법재판소의 취소 소송), 용어(`terms`). 글마다 근거(`basis`)를 단다. 받아 둔 글(`collected/archive/` 아래의 조약 조문, 법령, 공식 기록)을 근거로 삼을 때는 그 글에 실제로 있는 문구(`contains`)를 적고, 프로그램이 맞춰 본다. 자동으로 받을 수 없는 공식 화면은 읽고 확인한 날(`checkedOn`)을 적는다.
- 검사: `python -m tools.publish.procedures`(꼴, 높임말, 용어, 근거). 사이트를 만들 때는 꼴과 표기만 막고, 근거로 적은 문구가 받아 둔 글에서 사라진 것('근거 어긋남')은 알리기만 한다. 상태 점검(`tools/run/rules_health.py`)이 둘 다 일일 보고의 문제로 올린다. 근거는 되도록 끝난 절차의 기록이나 조문처럼 바뀌지 않는 글에서 댄다(진행 중인 절차의 기록은 단계가 바뀌면 글이 달라진다).
- 근거로 쓰는 조약 조문과 절차 문서는 `tools/archive/primary.py`가 EU 출판국에서 받아 `collected/archive/pages/eu-primary/`에 둔다(EU 조약과 EU 기능조약의 조문, 두 의정서, 규정 (EU) No 182/2011, 더 나은 법 제정에 관한 기관 간 합의, EEA 협정 제7부, 사법재판소 절차규칙의 기한 조문).
- 규제 쪽의 값(`data/regulations.json`): 따르는 절차(`procedure`), 연혁의 사건이 일어난 단계(`step`), 지금 와 있는 단계(`stepNow`), 날짜는 연혁에 없지만 공식 글로 확인되는 단계의 사실(`stepNotes`), 덧붙임(`procedureNote`). 뜻과 셈은 `tools/publish/rule_steps.py`의 머리글에 있다. 사이트에 실을 때 단계마다의 상태(마침, 진행 중, 다음, 기록 없음, 남음)를 셈해 `progress`로 붙이고, 안에서만 쓰는 값은 뺀다.
- 고치기: `python -m tools.publish.rule_steps --id <규제>`로 단계의 이름과 지금 상태를 보고, `rule_edit`의 `add-event --step`, `step`, `step-note`, `set --step-now`, `set --procedure`로 고친다. 사건에 단계를 적는 것은 그 단계의 일이 실제로 있었다는 뜻이고, `stepNow`는 그 단계에 와 있다는 기록이 있을 때만 적는다(짐작으로 적지 않는다).
- 큰 단계(`at`)와 세부 단계는 서로 맞아야 한다. 절차의 단계에 적힌 `reach`가 그 단계에 이르면 큰 단계가 적어도 어디까지 와 있어야 하는지다. 어긋나면 검사가 '단계 어긋남'으로 알린다. 고치는 도중에 잠깐 생기는 것이어서 `rule_edit`와 사이트 만들기는 막지 않지만, `python -m tools.publish.regulations`는 문제로 세므로 올리기 전에 없애야 한다.
- 화면: 셈은 `site/js/procedure/model.js`(node로 시험한다), 함께 쓰는 조각은 `site/js/procedure/parts.js`, 입법 절차 화면은 `site/js/views/procedure.js`와 `views/procedure/`(한눈에 보기 `board`, 기관 `who`, 법령의 종류 `acts`, 절차 `kind`), 규제 화면의 세부 절차는 `site/js/views/rules/steps.js`, 모양은 `site/css/procedure.css`다.
- 이 화면이 풀이한 용어는 글 속 용어 풀이에도 실리고(`tools/publish/gloss.py`), 용어집의 같은 용어에는 이 화면으로 가는 링크가 붙는다(`tools/publish/crossrefs.py`).
- 시험: `tests/test_procedures.py`(자료의 검사), `tests/test_rule_steps.py`(상태의 셈, 어긋남, 고치는 명령), `tests/test_procedure_view.py`(화면의 셈). 실린 규제는 날마다 단계가 바뀌므로 시험은 만든 표본으로 셈을 확인하고, 실린 자료로는 꼴만 본다.

## 법령에서 옮겨 온 참고 자료

소식이나 규제의 연혁과 달리, 법령에 적힌 값을 그대로 옮겨 화면의 그림과 계산에 쓰는 자료가 있다. 모두 같은 틀을 따른다: 원본은 `data/`에 있고 항목마다 그 값이 적힌 법령 글(`collected/archive/pages/` 아래)을 가리키며, 검사 프로그램(`tools/publish/`)이 값과 대목을 그 글과 대조한다. 꼴이 깨지면 사이트 만들기가 멈추고, 받아 둔 글과 달라진 것('근거 어긋남')은 알리기만 한다. 공개용 사본에서는 저장소 안의 경로와 대조용 대목을 뺀다. 어긋남은 상태 점검(`tools/run/reference_health.py`)이 일일 보고의 문제로 올린다.

- CBAM 계수(`data/factor.json`, 검사 `python -m tools.publish.factor`): 현행 지침과 개정안의 해마다의 값. 규제 자료에 `figure: cbam-factor`가 적힌 규제의 화면에 그림으로 실리고(`site/js/ui/factorchart.js`), 인증서 비용 추정이 쓴다.
- 실무 달력(`data/duties.json`, 검사 `python -m tools.publish.duties`): 법령에 날짜가 적힌 EU CBAM과 영국 CBAM의 의무. 일정 화면의 '의무 일정'에 실리고 일정에도 합쳐진다(같은 일을 가리키는 게시 데이터의 일정은 의무 쪽을 남긴다). 날짜가 법령이 아니라 공식 안내에만 적힌 일정(영국 CBAM 등록 개시)은 글에 그렇다고 밝힌다. 글이 날짜가 적힌 글 밖의 다른 글(다른 법령의 조문, 공식 안내)에도 기대면 `evidence`의 `also`에 그 글의 근거를 더 적고, 검사가 함께 대조한다.
  - 의무마다 누구의 일인지 적는다(`roles`: 신고인·수입자, 제3국 사업자, 검증기관, 영국 수입자). 화면에서 역할로 골라 보고, 고른 역할은 주소에 남는다(`#calendar-2027.role-verifier`, `site/js/calendar/roles.js`).
  - 해마다 돌아오는 의무에는 `yearly`를 적는다. 사이트를 만들 때 법령이 정한 날짜로 올해에서 두 해 뒤까지 펴서 싣고(`duties.expanded`), 뒤 해의 제목과 글이 달라야 하면 `yearly` 안에 적는다(`{prev}`는 그 전해). 만든 일정의 id는 `<id>-<해>`여서 같은 꼴의 id를 따로 적으면 검사가 막고, 2월 29일의 의무에는 `yearly`를 붙일 수 없다.
  - 검증기관이 알아 둘 것은 `verifier`에, 생산자가 준비할 것은 `supplier`에 적는다. 값과 대목은 다른 참고 자료처럼 받아 둔 법령의 글과 대조한다.
- 인증서 비용 추정(`data/calc.json`과 `data/calc-goods.json`, 검사 `python -m tools.publish.calc`): 사이트의 '품목·비용 > 비용 추정' 화면(`#calc`)이 쓴다.
  - `calc-goods.json`은 손으로 고치지 않는다. 받아 둔 법령의 표(`collected/archive/pages/eu-tables/`)에서 `python -m tools.calc.build`가 만든다: 무상할당 조정 이행규정 (EU) 2025/2620 부속서 5의 CBAM 벤치마크(품목 570개)와, 기본값 이행규정 (EU) 2025/2621 부속서 I(정정 규정 (EU) 2026/1740이 갈아 끼운 표)의 대한민국 표, 대한민국의 값이 없는 품목에 쓰는 '그 밖의 나라와 영역' 표. 법령이 정하지 않은 경우를 만나면 어림하지 않고 멈춘다.
  - `calc.json`은 손으로 적는 규칙이다: 마크업, 부문 간 보정계수, 벤치마크의 연도 구간, 생산경로의 이름, 계산식, 화면에 싣는 설명 글, 계산에 나오는 용어의 풀이(`glossary`. 화면의 '용어 풀이' 칸에 실린다. 높임말로 적고, 풀이마다 근거 대목을 단다). 근거는 모아 둔 공식 기록(`collected/archive/`)이나 EU 집행위원회 문서에서 뽑은 본문(`originals/text/`)의 대목이다. 수식은 법령의 받아 둔 글에 그림으로만 있어, 식은 집행위원회 가이던스 4의 글과 대조하고 식의 항이 무엇인지는 법령의 글과 대조한다. 탄소가격 차감의 식(이행규정 (EU) 2026/2498 제7조와 부속서 I)은 가이던스에 없어 관보 PDF(`collected/archive/pdfs/32026R2498.pdf`)에서 확인했고, 그 사실을 항목의 `note`에 적어 둔다.
  - 셈은 `site/js/calc/`가 한다(시험은 `tests/test_calc.py`와 `tests/test_calc_detail.py`가 node로 돌린다): 한 해의 추정과 연도별 추정은 `compute.js`, 법령의 표에서 값을 고르는 일은 `tables.js`, 전구물질 한 줄은 `precursor.js`, 탄소가격 차감과 기준가격은 `carbon.js`, 기본값과 같아지는 직접배출량은 `breakeven.js`, 내려받는 표의 줄은 `export.js`. 정해지지 않아 가정한 값(2031년 이후의 벤치마크와 부문 간 보정계수)과 참고용인 값(2027년 수입분부터 갱신될 벤치마크)은 화면이 그렇다고 밝힌다.
  - 신고 방법은 둘이다. 기본값으로 신고: 기본값 × (1 + 마크업)에서 'B열 벤치마크 × CBAM 계수 × 부문 간 보정계수'를 뺀다. 실제 배출량으로 신고: 직접배출량과 (간접배출량을 세는 품목이면) 간접배출량을 넣는다. 전구물질을 따로 넣지 않으면 B열 벤치마크로 어림하고(화면이 어림이라고 밝힌다), 따로 넣으면 법령의 식대로 'A열 벤치마크 × CBAM 계수 × 부문 간 보정계수 + Σ(제품 1톤에 들어간 양 × 전구물질의 고유 내재무상할당량)'으로 셈한다. 전구물질의 비워 둔 값은 대한민국 기본값 + 마크업, B열 벤치마크로 정한다.
  - 인증서 가격(`site/js/calc/prices.js`, 칸은 `views/calc/price.js`): 수입 연도에 맞는 가격을 넣어 둔다. 2026년 수입분에는 수입한 분기의 가격이 적용되므로(이행규정 (EU) 2025/2548 제1조(6)) '수입 분기'를 고르게 하고, 게시 전인 분기에는 게시 예정일을 적는다. 2027년부터는 인증서를 사는 때의 주간 가격이 적용되므로(제5조) 가장 최근에 게시된 가격을 넣어 두고 그렇다고 적는다. 가격을 손으로 고치면 '직접 넣기'가 되어 연도를 바꿔도 덮어쓰지 않는다. 그해의 가격 평균(`yearMean`)은 탄소가격 차감의 기준가격과 인증서 가격 화면의 '연평균 가격'이 함께 쓴다(시험은 `tests/test_calc_prices.py`).
  - 탄소가격 차감(제3국 탄소가격 차감 이행규정 (EU) 2026/2498 제7조): 실질적으로 지불된 탄소가격(인증보고서의 값, 또는 탄소가격·무상 몫·환율로 계산한 값) ÷ 기준가격, 또는 기본 탄소가격 × 신고한 내재배출량 ÷ 기준가격. 기본값으로 신고하면 기본 탄소가격으로만 넣을 수 있다. 기준가격은 수입한 해의 것으로 공개된 인증서 가격(`data/prices.json`)의 평균이고(그해의 가격이 더 남아 있으면 지금까지의 평균이라고 밝힌다), 그해의 가격이 없으면 넣은 인증서 가격을 쓴다. 기본 탄소가격과 원화 탄소가격, 환율은 사이트에 값이 없어 쓰는 사람이 넣는다.
  - 화면(`site/js/views/calc.js`와 `views/calc/`): 넣는 칸은 `fields`(공통 도우미), `picker`(품목 찾기), `actual`(내재배출량과 생산경로), `precursors`(전구물질), `carbon`(탄소가격 차감), 결과는 `result`(수치와 막대), `steps`(계산 내역), `compare`(기본값과 견주기), `yearly`(연도별 표), `basket`(여러 품목 모아 보기), 넣은 값을 탭에 남겨 두는 일은 `memory`(sessionStorage. 서버로 보내지 않는다). 연도별 표와 담아 둔 추정은 CSV로 내려받을 수 있다(`site/js/ui/csv.js`, `ui/save.js`).
  - 활동자료(연료 사용량 등)에서 배출량을 계산해 주지는 않는다. 넣는 값은 제품 1톤당 배출량과 탄소가격이다.
  - 근거 법령을 고치거나 바로잡는 새 문서가 법령 데이터베이스 목록에 보이면 상태 점검이 알린다(`calc.json`의 `watch`). 그때는 `tools/archive/tables.py`의 대상을 새 법령으로 바꿔 표를 다시 받고(워크플로 '소급 수집', `steps`에 `eu-tables`), `python -m tools.calc.build`로 자료를 다시 만든다. 무엇이 달라졌는지는 `python -m tools.calc.changes`가 품목마다 견준다(기본값과 그 값이 온 행, 벤치마크, 새로 생기거나 없어진 품목. 앞의 자료는 git에 올라가 있는 것이고, `--json`으로 받으면 사이트에 '바뀐 값'을 실을 때의 자료가 된다. 달라진 것이 없으면 0, 있으면 1, 자료를 읽지 못했거나 꼴이 달라 견주지 못했으면 2로 끝난다). 확인한 뒤 반영한 문서를 `watch.known`에 적는다.
- 규제 화면에서 추정 화면으로 이어 주려면 규제 자료에 `tool: calc`를 적는다(`python -m tools.publish.rule_edit set --id <규제> --tool calc`).

## 규정 원문과 국문 번역

사이트의 '원문·자료 > 규정 원문'(`#laws`, `#law-<문서 id>.<조각>`)은 CBAM 규정(통합본)과 이행·위임규정의 원문을 국문 번역과 문단마다 나란히 보여 주고, 전체 규정에서 낱말이나 질문으로 조문을 찾게 한다. 규제 하나의 화면(`#rules-<규제>`) 오른쪽 칸에도 같은 찾기가 있다.

- 원문은 저장소에 받아 둔 EU 법령의 글이다(`collected/archive/pages/eu-fulltext/cbam-consolidated.txt`, `collected/archive/pages/eu-acts/`). 사이트 폴더를 만들 때 `tools/laws/build.py`가 조와 문단으로 나눠 `data/laws/`(목록 `index.json`, 법령마다의 본문, 검색에 쓰는 `search.json`)를 만든다. 싣는 법령과 차례는 `tools/laws/catalog.py`가 정한다.
- 번역은 `data/laws-ko/<법령 번호>.json`에 있다. 문단의 자리가 아니라 원문 문단의 글자에서 만든 열쇠에 붙는다. 그래서 통합본이 새로 나와도 글자가 그대로인 문단의 번역은 남고 바뀐 문단만 다시 옮기면 되며, 여러 법령에 똑같이 나오는 문단은 한 번만 옮긴다.
- 옮기는 차례: `python -m tools.laws.todo [--limit 글자 수] [--act 법령] [--titles]`가 다음 문단과 그 글에 나온 용어집의 낱말을 주고, 옮긴 것을 `{"blocks": {열쇠: 국문}}` 파일로 만들어 `python -m tools.laws.apply <파일>`에 넘긴다. 진행 상황은 `python -m tools.laws.status`.
- 검사에 걸린 문단: `apply`는 걸린 문단마다 걸린 횟수와 마지막 까닭을 번역 자료의 `held`에 적는다(번역이 들어가면 빠진다). 걸린 문단은 번역이 없어 줄의 맨 앞에 남으므로, 그런 문단이 쌓여 묶음을 채우면 번역이 나아가지 못한다. 그래서 `todo`는 세 번 걸린 문단을 다른 문단을 모두 옮긴 뒤로 돌리고(다음에 줄 때 앞의 까닭을 `remarks`에 함께 준다), 그때도 걸려 여섯 번이 되면 더 주지 않는다. 뒤로 돌린 문단의 수는 `status`의 전체 줄 끝에 나오고, 끝내 싣지 못한 문단은 실행 확인과 보고가 문제로 알린다(`tools/run/laws_health.py`). 웹 주소 안의 낱말은 옮길 말로도 용어집과 견줄 말로도 보지 않고, 주소와 번호만 있는 줄(주소 하나만 적은 각주)은 옮기지 않고 그대로 싣는다. 번역이 영문 그대로 둔 용어(화면에 적힌 이름)에는 국문 표기를 요구하지 않는다. 핵심 용어가 다른 뜻으로 쓰인 자리(installation of wind turbines의 '설치')는 `sources/translation.json`의 `senses`에 그 뜻의 표기를 적어 두면 막지 않고 알리기만 한다. 용어집이 쓰지 않기로 한 표기도 원문에 그 표기가 맞는 다른 낱말이 있으면(precision의 '정밀도') `senses`를 보고 알리기만 한다. 식과 화면에 뜨는 번호 붙은 알림 글(VAL748 …)은 원문대로 두어도 막지 않고, 원문의 각주 표시("[16]")는 번역에도 같은 수만큼 있어야 하고, 번역이 수를 갈라 적으면(2551 → 255[1]) 수가 빠진 것으로 막는다. 원문의 주소(https://…)가 번역에 그대로 있지 않아도 막는다(붙임표 하나만 빠져도 열리지 않는다). 걸린 문단은 `python3 -m tools.laws.held`로 보고(열쇠, 까닭, 원문), 까닭을 고친 뒤 `--reset`으로 걸린 횟수를 지우면 다음 묶음에 다시 나온다.
- 넣기 전의 검사(`tools/laws/check.py`): 원문의 수(날짜, 조 번호, 금액)가 번역에 모두 있는지, 부속서·장의 로마 숫자가 남아 있는지, 용어집이 쓰지 않기로 한 표기가 없는지, 원문에 핵심 용어(용어집의 `core`)가 나오면 번역에 그 국문 표기가 있는지를 본다. 걸린 문단은 넣지 않는다. 원문에 없는 수, 길이가 크게 다른 번역, 원문에 없는 글머리표로 시작하는 번역은 넣되 알린다(번역하는 실행이 읽고 고친다). 사람의 감수를 대신하는 검사는 아니다.
- 영문 병기: 번역 자료에는 국문만 두고, 사이트 자료를 만들 때 `tools/laws/gloss.py`가 핵심 용어에 영문을 괄호로 붙인다(조 하나에서 처음 나올 때 한 번, 원문 문단에 그 영문이 있을 때만). 용어집을 고치면 화면의 병기도 따라 바뀐다.
- 찾기(`site/js/laws/engine.js`): 질문에서 용어집의 낱말을 찾아 그 영문 표기로 원문을, 국문 표기로 번역과 조의 이름을 찾는다(번역이 없는 조문도 국문 질문으로 찾힌다). 문장을 지어 답하지 않고 낱말이 나온 조문의 위치만 알려 준다. 화면의 '찾은 낱말'에 어떤 영문 표기로 찾았는지 보인다.
- 번역은 비공식이다. 화면이 그렇다고 밝히고 EUR-Lex의 원문으로 이어 준다. 통합본은 EU가 참고용으로 내는 문서라는 것도 함께 밝힌다.
- 인용 복사(`site/js/laws/cite.js`): 문단 오른쪽의 표시나 조각 머리의 '인용 복사'를 누르면 원문, 국문, 출처(문서·조·PDF 쪽·판), 그 문단으로 바로 가는 주소(`#law-<문서>.<조각>.<문단 차례>`)가 함께 복사된다. 아직 옮기지 않은 문단은 국문 줄 없이 복사된다.
- 부속서: 부속서가 규칙의 글인 법령(산정 방법 (EU) 2025/2547, 검증 원칙 2025/2546, 인정 조건 2025/2551, 대륙붕·배타적 경제수역 2025/2210, 제3국 탄소가격 차감 2026/2498)은 부속서도 온전히 받아 싣는다(`tools/archive/acts.py`의 `WHOLE`). 값의 표인 부속서(기본값, 벤치마크)와 전환기간 규정의 부속서는 앞부분만 받아 두고, 화면이 그 부속서의 끝에 싣지 않은 줄 수와 원문 링크를 알린다(조각의 `cut`). 법령의 수식은 원문에 그림으로 실려 있어 번호만 남으므로, 그런 부속서의 머리에 원문에서 보라고 알린다(`formulas`).
- 달라진 곳 보기(`#changes-<문서>`): 문서의 앞선 판과 지금의 판을 문단 단위로 견줘 바뀐 곳, 더해진 곳, 빠진 곳을 원문과 국문으로 보여 준다. 갈래 하나만 골라 보면 차례도 그 갈래의 문단이 있는 조각과 그 수로 바뀐다.
  - 앞선 판: 법령은 처음 관보에 실린 글과 지난 통합본을 받아 남겨 둔다(`tools/archive/earlier.py`, `collected/archive/pages/eu-earlier/`. 새 통합본으로 갈아 끼울 때 그때까지 쓰던 글이 여기로 간다). 안내 문서는 원문 대장이 남겨 둔 지난 판을 쓴다.
  - 견주기는 `tools/laws/compare.py`가 한다: 번호가 같은 문단끼리 짝짓고, 각주 번호가 밀린 것과 따옴표·줄표의 꼴만 다른 것, 줄이 합쳐지거나 갈린 것은 같은 것으로 본다. 판의 차례와 공개 자료(`data/laws/changes/<문서>.json`)는 `tools/laws/revisions.py`가 만든다. 낱말 단위의 표시는 화면이 한다(`site/js/laws/worddiff.js`).
  - 앞선 판에만 있는 문단(바뀌기 전의 글, 빠진 글)도 국문으로 보이도록, 그런 문단만 담은 숨은 문서(`<문서>-was-<판의 날짜>`)를 번역과 검수의 줄에 세운다(`corpus.everything(history=True)`). 사이트의 목록과 검색, PDF에는 싣지 않는다. 번역 자료에서 쓰이지 않는 번역을 지울 때 이 문서가 쓰는 것은 남겨야 한다.
- 조문 잇기(`tools/publish/crossrefs.py`, `data/refs.json`): 소식의 글, 의무 일정의 근거, 용어집의 근거 조문에 적힌 법령과 조·부속서를 이 화면의 그 자리로 잇는다. 글에 법령(번호나 이름)과 그 바로 뒤의 조가 또렷이 적힌 곳만 잇고("CBAM 규정 제6조(1), 제22조(1)"), 법령 없이 적힌 조나 다른 법의 조문은 잇지 않는다. 조와 부속서의 끝에는 그 조가 근거인 의무 일정, 그 조를 적은 소식, 그 조에서 나온 용어를 접어서 보여 준다. 근거 칸에 적힌 조각이 사이트의 글에 없으면 상태 점검이 알린다(`tools/run/reference_health.py`).

### 안내 문서(가이던스, 등록부 안내서, 보고서)

같은 화면에 EU 집행위원회가 낸 문서도 싣는다. 무엇을 싣는지는 `sources/guides.json`이 정하고, 갈래(`group`)는 셋이다.

| 갈래 | 싣는 것 |
|---|---|
| `guide` 가이던스와 질의응답 | 가이던스 1~5f, 질의응답, 검증·인정 가이던스, 전력 질의응답, 제27a조(안) 질의응답 |
| `manual` 등록부 이용 안내서 | 사업자·검증기관 포털과 신고인 포털의 안내서, 접근 신청·권한 위임 절차, 한 장 요약, 개인정보 처리 고지 |
| `paper` 보고서와 안내 자료 | 한 장짜리 안내 자료(대상 제품의 수입 여부 확인, 실제값과 기본값, CBAM 인증서의 운용 방식), 이행규정 의견수렴 결과 요약, 개발도상국 안내, 전환기간에 쓰던 수입자 가이던스와 부문별 생산자·수입자 안내 자료 |

- 원문은 원문 대장이 받아 둔 PDF다. 문서가 새 판으로 바뀌면 그 판을 쓰고, 글자가 그대로인 문단의 번역은 남는다.
- 문단은 PDF에 적힌 짜임(구조 꼬리표)에서 읽는다. 집행위원회 PDF는 거의 모두 제목, 문단, 목록 항목, 표의 칸, 그림 제목, 각주가 무엇인지 파일 안에 적혀 있다. `tools/pdfko/units.py`가 이것을 뜻 단위로 읽어 `originals/units/`에 두고(수집 워크플로가 새 PDF를 받으면 만든다), `tools/laws/unit_segment.py`가 단위에서 조각을 만든다. 머리말·꼬리말과 쪽 번호, 차례는 싣지 않는다. 표의 칸은 줄과 칸의 자리를 함께 적어 화면이 표로 그리고(합쳐진 칸은 글의 가로 자리로 헤아린다), 본문에 붙은 각주 번호는 그 번호의 각주가 있을 때 `[3]`으로 적는다.
- 문단을 나누는 방식이 바뀌어 띄어쓰기나 글머리표만 달라진 문단에는 옛 번역을 옮겨 붙인다(`tools/laws/carry.py`). 글자와 숫자가 같을 때만 붙이고, 검사를 지나지 못하면 붙이지 않는다.
- 꼬리표가 없는 PDF(한 장 요약 1건)와 단위 파일이 없는 문서는 PDF에서 뽑은 글(`originals/text/`)을 줄 단위로 나눈다: `tools/laws/pdf_pages.py`가 되풀이되는 머리말·꼬리말, 쪽 번호와 차례 쪽, 쪽 아래의 각주를 가려내고(본문에 붙은 각주 번호는 `[3]`으로 바꾼다), `pdf_blocks.py`가 줄을 문단으로 묶고, `guide_segment.py`가 번호 붙은 제목마다 절로 나눈다. 표의 칸이나 본문의 수를 제목으로 잘못 보지 않도록 번호의 차례와 차례 쪽의 번호·제목을 함께 본다. 차례가 번호의 단과 제목의 단으로 나뉜 문서(등록부 안내서)는 둘을 차례대로 짝지어 쓴다. 제목 꼬리표가 없는 문서는 이 방식으로 찾은 제목을 빌려 쓴다. 단위 파일이 없는 PDF 문서는 실행 확인(`tools/run/laws_health.py`)이 알린다.
- 꼬리표가 없는 도안 자료(흐름도, 여러 칸으로 짠 한두 쪽짜리 안내 자료)는 줄 단위로 나누면 한 상자의 글이 줄마다 다른 문단으로 갈리고 읽는 차례가 뒤섞인다. 그런 문서는 `sources/guides.json`에 `"units": "layout"`으로 적어 쪽에 놓인 글 상자대로 읽는다(`tools/pdfko/boxes.py`): 상자 하나가 문단 하나이고, 상자들 사이의 빈 틈으로 쪽을 갈라 읽는 차례를 정하며(칸 제목 다음에 그 칸의 글, 흐름도는 윗줄부터), 쪽 가장자리에 세로로 누운 글(발간 번호, 저작권 표시)은 싣지 않는다. 번호만 작게 적힌 상자가 옆의 줄을 가리키면 그 줄을 각주로 읽고, 글 안에 올려 적은 번호는 `[1]`로 적는다. 꼬리표가 없는 PDF의 단위 파일에는 늘 이렇게 읽은 단위가 들어 있지만, 그렇게 적은 문서에서만 쓴다(나누는 방식이 바뀌면 이미 옮긴 번역이 떨어지므로 문서마다 정한다). `"units": false`면 단위를 쓰지 않는다.
- 꼬리표로 읽을 때에도 조판 프로그램이 남긴 제어 글자(여기까지 들여쓰기 표시 U+0007)는 지우고, 세로로 누운 글은 낱말마다 띄어 잇는다.
- 문서마다 제목을 찾는 방식을 정할 수 있다(`outline`). `auto`가 기본이고, `loose`는 차례가 없는 문서에서 "1. Introduction" 꼴의 제목까지 받으며, `none`은 제목을 찾지 않고 글 전체를 조각 하나(본문)로 둔다. 도안으로 된 한두 쪽짜리 자료는 글의 차례가 뒤섞여 뽑히므로 `none`으로 싣는다.
- 화면에 함께 보일 알림은 `remark`에 적는다(전환기간용 자료, 아직 채택되지 않은 조문, 도안으로 된 자료).
- 싣지 않는 것: 표 파일(xlsx)과 묶음 파일(zip), 기관의 이름과 연락처만 늘어놓은 문서, 새 판이 나와 지난 판이 된 문서. 까닭은 `sources/guides.json`의 `note`에 적는다.
- 화면은 문단의 꼴대로 그린다(`site/js/laws/blocks.js`): 목록 항목은 들여 쓰고, 표는 칸마다 원문과 국문을 위아래로 두며, 그림 안의 글자는 접어 둔다. 식과 그림은 원문 PDF에서 확인하라고 밝힌다.
- 원문과 번역을 PDF로 나란히 볼 수 있다(`#pdf-<문서>.p<쪽>`). `tools/pdfko`가 원문 PDF에서 번역이 있는 문단의 글자만 들어내고 같은 자리에 국문을 찍어 국문 PDF를 만든다. 쪽 수와 쪽의 크기가 같으므로 화면은 한 줄에 원문 쪽과 번역 쪽을 두어 함께 스크롤한다(PDF.js, `site/vendor/pdfjs`). 국문 PDF는 사이트를 만들 때 만들고(`tools/pdfko/site.py`), 입력이 같으면 만들어 둔 것을 쓴다(`.cache/pdfko`). 배포할 때 만들지 못한 문서는 지난 배포의 것을 그대로 싣고 목록(`data/laws/pdf.json`)에 그렇게 적으며, 상태 점검이 알린다. 번역이 모두 준비된 문서는 모두 나란히 보기에 싣는다. 싣지 않는 것은 저장소에 원문 PDF의 사본을 두지 않은 문서뿐이다(`sources/guides.json`에 `"side": false`로 적는다. 글로 보기에는 그대로 실린다).
  - 법령은 관보 PDF로 싣는다. `tools/archive/actpdf.py`가 EU 출판국 자료 창구에서 법령마다 PDF를 받아 `collected/archive/pdfs/<CELEX 번호>.pdf`에 두고 목록(`collected/archive/eu-pdfs.json`)에 온 곳과 쪽 수, 해시를 적는다. 한 법령에 파일이 여럿이면 차례대로 이어 붙인다. 날마다의 수집이 받아 두지 않은 것만 받고(새로 싣는 법령, CBAM 규정의 새 통합본), 더는 싣지 않는 판의 파일은 지운다. 받지 못한 법령은 실행 확인이 알린다. 나라별 기본값의 표가 수천 쪽인 두 법령(기본값 이행규정과 그 정정 규정)은 일부 쪽만 둔다(`actpdf.KEEP`: 조문과 부속서의 머리말, 간접배출·전력의 기본값, 대한민국과 '그 밖의 나라'의 표). 화면은 몇 쪽 가운데 몇 쪽을 실었는지 밝히고 EUR-Lex의 온 파일로 잇는다. 법령의 PDF에는 구조 꼬리표를 쓰지 않고 글을 맞추어 자리를 찾는다(`match`).
  - 쪽마다 비공식 번역임을 적고 첫 쪽에는 띠로 알린다. 꼬리표에 기관의 표장이라고 적힌 그림은 가린다. 도안으로 그려져 꼬리표로는 찾을 수 없는 표장과, 그림으로 박혀 지울 수 없는 제목의 그림자는 문서마다 가릴 자리를 적어 가린다: `sources/guides.json`의 `covers`에 묶음의 이름으로 자리를 적고(쪽과 네모 `box`, 또는 그 글이 놓인 줄 `over`와 넓힐 만큼 `pad`. 칠할 빛깔 `fill`, 가린 자리에 비공식 번역본임을 적을지 `label`, 양 끝을 둥글릴지 `round`), 문서에는 `"cover": "<묶음 이름>"`으로 적는다. 같은 틀로 만든 안내 자료들은 한 묶음을 함께 쓴다. 번호와 글머리표, 각주 번호, 번역하지 않는 글(수식, 쪽 번호, 머리말·꼬리말, 문서의 짜임 밖에 적힌 작은 글)은 원문 것이 그대로 남는다. 차례 쪽에는 번호가 같은 조각의 제목 번역을 앉히고 점줄과 쪽 번호는 둔다. 가로로 놓인 쪽(돌려 놓은 표)은 고치지 않고 원문 그대로 둔다.
  - 화면은 쪽의 그림 위에 보이지 않는 글자 층을 얹는다(`site/js/pdf/sheets.js`, PDF.js의 `TextLayer`). 그래서 글자를 끌어서 고르고 복사할 수 있다. 번역 쪽의 글자 층은 사이트의 글꼴로 놓아 그림의 글자와 자리를 맞추고, 글자 층마다 언어를 적는다(브라우저가 언어에 따라 `serif` 같은 글꼴 이름을 다른 글꼴로 풀어, 적지 않으면 영문 조각이 그림보다 넓게 놓인다). 쪽은 화면 가까이에 올 때만 그리므로 브라우저의 찾기로는 보이는 쪽밖에 찾지 못한다. 그래서 도구 줄의 찾기 칸이 문서 전체에서 찾는다(`site/js/pdf/find.js`가 쪽마다 글자를 읽어 찾고 찾은 곳을 칠하며, `findbar.js`가 칸과 단추를 만든다. Ctrl+F나 ⌘F를 누르면 이 칸으로 가고, 한 번 더 누르면 브라우저의 찾기가 열린다). 원문 쪽은 영문으로, 번역 쪽은 국문으로 찾는다.
  - 번역이 원문보다 길면 아래 빈 곳을 쓰거나 글자를 줄인다(0.6배까지). 그래도 자리가 모자라거나 줄들이 문단 꼴이 아니면 그 문단은 원문 그대로 둔다. 글꼴은 `assets/fonts`의 Pretendard다(OFL 1.1). 원문이 굵은 글씨인 곳만 굵게 찍는다.
- 찾기에 쓰는 글은 법령의 것(`data/laws/search.json`)과 따로 둔다(`search-guides.json`). 크기가 커서 규정 원문 화면에서 찾을 때만 받는다.

### 자동으로 받지 못하는 문서

EU 집행위원회의 문서 링크 가운데 몇은 자동 실행의 요청을 받아 주지 않는다(403: EU 출판국의 내려받기로 넘어가는 한 장짜리 안내 자료들). 그런 문서는 원문 대장의 `pending`에 남고, 세 번 실패하면 주간 보고가 이름을 적어 알린다. 막힌 주소를 다른 길로 받으려 하지 않는다. 사람이 브라우저로 받은 파일을 넣는다.

- `python3 -m tools.originals.supply --list`가 받지 못한 문서의 번호와 이름을 보여 준다. `python3 -m tools.originals.supply <문서 번호> <파일>`이 그 파일을 대장에 넣는다(사본, 뽑아 낸 본문, 판 정보. 다른 문서와 같은 꼴이다). 파일 이름은 받은 그대로 둔다(EU 출판국의 발간 번호가 들어 있다).
- 넣은 문서에는 `supplied`(넣은 날)가 적히고, 자동 실행은 그 문서를 다시 받으려 하지 않는다(받아 주지 않는 주소를 날마다 두드리지 않고, 이어진 실패를 접속 제한으로 잘못 보지 않게 한다). 그래서 같은 주소의 파일이 새 판으로 바뀌었는지는 스스로 알지 못한다. 화면에서 링크가 사라지거나 새 링크가 생기는 것은 전과 같이 알린다. 새 판을 받았으면 같은 명령으로 다시 넣는다(본문이 같으면 넣지 않는다).
- 문서 안에 EU의 것이 아닌 그림이 있다고 적혀 있으면(`Image Source: stock.adobe.com`) `--no-copy <까닭>`으로 넣는다: 사본은 저장소에 두지 않고 본문과 뜻 단위만 받아 둔다. 원문 대장은 그 문서를 EU 집행위원회의 주소로 잇는다. EU 집행위원회 문서의 재이용 허락은 남의 것인 요소에는 미치지 않기 때문이다(아래 '자료의 재이용').
- 넣은 뒤에는 `python3 -m tools.pdfko.units --missing`으로 뜻 단위를 만들고, 규정 원문 화면에 실을 문서면 `sources/guides.json`에 올린다(부문만 다루는 문서는 `sources/sectors.json`에도). 번역은 날마다의 「번역」 실행이 이어서 한다.
- 2026-11-14에 이렇게 넣은 것: 한 장짜리 안내 자료 3건, 철강 생산자 안내 자료 1건, 부문별 수입자 안내 자료 6건. 남은 것은 법령·가이던스 화면의 이름 없는 링크 1건이다.

### 번역을 하는 실행

- 번역은 예약 실행이 한다. 실행마다 무엇을 얼마나 옮기는지는 `sources/translation.json`이 정한다(`python -m tools.laws.todo --runner <이름>`). 갈래를 다른 실행으로 옮길 때는 그 파일만 고친다.
- 실행은 앞의 실행을 기억하지 못한다. 용어집에 없는 전문용어를 어떻게 옮겼는지는 `language/translation-terms.json`에 적어 두고(`tools.laws.wording`), 다음 묶음을 받을 때 그 글에 나온 낱말이 함께 나온다. 확인된 표기가 아니므로 운영자가 살펴 용어집으로 옮긴다. 용어집이 앞선다: 용어집에 든 낱말은 적지 않고, 적어 둔 뒤에 용어집에 들어간 낱말은 건네지 않는다(용어집의 표기와 옛 표기가 함께 건네지지 않게). 그런 낱말은 `python -m tools.laws.wording prune`으로 파일에서 지운다.
- 모델이나 방법을 견줄 때는 `trials/request.json`으로 시험을 청한다(`tools.laws.trial`). 이미 실린 번역을 보여 주지 않고 같은 문단을 다시 옮기게 해서 두 번역을 견준다. 시험의 번역은 `trials/`에만 쌓이고 사이트에는 실리지 않는다.
- 넣을 때 용어집 낱말의 띄어쓰기를 권장 표기로 맞추고(`tools.laws.terms.unify`), 문장의 끝맺음을 한 가지 꼴로 맞춘다(`tools.laws.finish`: "…다"로 끝나면 마침표). 번역하는 쪽이 달라져도 화면의 영문 병기와 찾기가 같은 글자로 걸리고, 문단의 끝이 들쭉날쭉하지 않게 하려는 것이다.

- 번역과 검수는 서로 다른 예약 작업이 한다. 번역한 모델과 다른 모델이 읽게 하려는 것이다. 실행 하나가 읽고 쓸 수 있는 양에는 한도가 있어, 번역 실행의 몫은 번역 네 묶음이고 검수 실행의 몫은 검수 네 묶음이다(`sources/translation.json`). 더 빨리 하려면 몫을 늘리지 않고 실행을 더 자주 돌린다. 예약 작업 하나는 한 시간에 한 번까지만 돌 수 있으므로 같은 절차서를 따르는 예약 작업을 시각을 엇갈려 여럿 둔다. 실행들이 겹치지 않게, 실행은 시작할 때 `python3 -m tools.laws.lock take <실행 id> --work translate`(검수는 `--work verify`)로 차례를 잡고 끝날 때 `release`로 푼다. 자물쇠는 main에 올리는 파일 하나(`locks/translating.json`)이고, 먼저 올린 쪽만 잡는다. 이 파일은 어느 자동 실행의 경로에도 들지 않아 자물쇠만 바뀐 커밋은 검사나 배포를 돌리지 않는다. 잡은 채로 멈춘 실행의 자물쇠는 12분이 지나면 다음 실행이 걷어 낸다. 자기 일(옮길 문단이나 검수할 문단)이 없으면 실행은 차례를 잡지 않고 끝낸다(`take`가 3으로 끝난다). 번역이 다 끝난 뒤의 실행이 빈 커밋을 남기지 않게 하려는 것이다. 예약 작업의 지시문은 절차서를 읽기 전에 `python3 -m tools.laws.lock work --work translate`(검수는 `verify`)로 할 일이 있는지 먼저 묻고, "할 일 없음"이면 절차서를 읽지 않고 끝낸다(그런 날에는 운영 콘솔에 실행 기록이 남지 않는다). 번역이 모두 끝난 뒤의 실행이 날마다 긴 절차서를 읽지 않게 하려는 것이다.
- 번역은 묶음마다 저장소에 올라오지만 사이트는 실행이 끝날 때 한 번만 다시 실린다. 실행이 차례를 풀 때 지난번에 실은 뒤로 올라온 번역이 있으면 `stamps/translated.json`을 고쳐 함께 올리고, 사이트 배포와 화면 점검은 번역 파일(`data/laws-ko`)이 아니라 이 파일이 바뀔 때 돈다. 여러 실행이 묶음마다 배포를 돌리면 한 시간에 스무 번쯤이 되어 GitHub Pages가 권하는 횟수(한 시간에 열 번)를 넘기 때문이다. 틀려서 지운 번역(`language/translation-reviews.json`이 바뀜)은 기다리지 않고 바로 실린다. 자동 시험(도구 검사)도 묶음마다 돌지 않고 같은 표가 바뀔 때 한 번 돈다(번역은 넣을 때 이미 검사를 거친다).

### 번역의 검수

사이트에는 검수를 거친 번역만 싣는다(`tools.laws.corpus.published`). 한 번도 검수하지 않은 번역은 싣지 않고, 그 문단은 화면에 '번역 준비 중'으로 보인다. 화면은 번역의 퍼센트를 보여 주지 않는다: 다 실린 문서에는 아무 표시가 없고, 그렇지 않은 문서에만 '번역 준비 중'(실린 번역이 없음)이나 '일부 번역 준비 중'이라고 적는다(`site/js/laws/ready.js`). 번역이 다 실리지 않은 문서는 국문 PDF도 만들지 않는다. 검수를 마친 번역을 나중에 고치면(용어 맞추기, 같은 문장 맞추기) 그 문단은 번역 자료의 `passed`에 적혀 다시 검수할 때까지도 실리고, 검수에서 지워진 번역은 다시 옮겨 검수를 마쳐야 실린다(`tools/laws/store.py`).

번역은 넣을 때 기계 검사를 거친다. 검사는 수와 용어는 잡지만 뜻이 틀린 문장이나 빠진 말은 잡지 못한다. 그래서 세 겹으로 보고, 첫 겹(다른 모델의 검수)을 거친 번역만 사이트에 싣는다.

1. **모든 번역을 다른 모델의 실행이 원문과 견줘 읽는다**(`tools.laws.verify`). 번역 검수 실행이 번역 실행들이 옮겨 둔 문단을 읽는다(`verify todo`). 틀린 번역은 지우고 까닭을 적으며(`verify apply`가 `review.drop`을 부른다), 틀리지 않은 번역은 검수를 마친 것으로 적는다(번역 자료의 `checked`). 번역이 바뀐 문단은 `checked`에서 빠져 다시 읽힌다.
2. **검수가 제대로 읽는지 잰다.** 묶음마다 번역 몇 개를 일부러 틀리게 바꿔 섞어 넣는다(`tools.laws.spoil`: 의무와 허용, 포함과 제외 같은 말 뒤집기, 부정 빼기, 문장 빼기). 어느 것이 바꾼 것인지는 묶음에 적지 않는다. 한 번 바꿔 섞었던 문단은 한동안 다시 고르지 않는다(그 묶음을 버려도 다음에는 있는 그대로 읽힌다. 고른 문단은 `language/translation-checks.json`의 `canaried`에 남는다). 바꾼 것을 잡아낸 비율이 문턱(`sources/translation.json`의 `verify.catch`)보다 낮으면 그 묶음의 검수는 버린다. 바꾼 번역은 작업 파일(`.work/`)에만 있고 번역 자료나 사이트에는 들어가지 않는다.
3. **주마다 표본을 다시 읽는다**(주간 작업, `python -m tools.laws.review sample`). 날마다의 검수가 지나친 것을 한 번 더 걸러 내려는 것이다. 새로 옮기거나 고친 문서의 문단을 먼저 고르고, 모자라면 나머지 문서에서 채운다(번역이 다 끝난 뒤에도 표본이 비지 않는다). 앞선 판에만 있는 문단의 번역도 표본에 든다.

- 지워진 문단은 번역하는 실행이 까닭과 함께 다시 받는다(`todo`의 `remarks`, `language/translation-reviews.json`). 같은 문단을 두 번 지우고도 또 틀렸다고 하면 지우지 않고 '가리지 못한 문단'으로 적어 둔다(`language/translation-checks.json`의 `disputed`). 사람이 볼 것이다.
- 한 묶음에서 틀렸다고 한 비율이 지나치게 높으면(`verify.harsh`) 반영하지 않고 알린다.
- 날마다의 결과(읽은 묶음, 틀리지 않다고 본 문단, 지운 문단, 바꿔 섞은 번역과 잡아낸 수)는 `language/translation-checks.json`에 쌓인다. `python -m tools.laws.verify status`가 한 줄로 간추린다.
- 같은 문장은 같은 번역으로(`tools/laws/alike.py`): 여러 문서에 되풀이되는 같은 문장(가이던스마다 붙은 정의 목록, 법령을 옮겨 적은 문장)이 앞의 번호나 각주 번호, 끝의 문장부호만 달라 따로 옮겨지면 문서마다 조금씩 다르게 읽힌다. 이 도구가 그런 묶음을 찾아, 법령의 번역(없으면 가장 많이 쓰인 번역)을 바탕으로 나머지를 맞춘 글을 만든다. 문단의 번호와 각주 번호, 끝의 문장부호는 그 문단의 것을 지킨다. 번호로 보는 것은 띄어 쓴 번호와 글머리표뿐이고(`(EU) 2023/956`, `2026. 1. 1.`, `(c)호의`는 글이다), 번역에서 떼는 번호는 원문에 있는 수까지다. 번역의 번호가 원문과 맞지 않는 문단은 맞추지 않고 알린다. 묶음마다 검토해 골라 둔 바탕은 `language/alike-picks.json`에 있고 그것이 먼저다. `python -m tools.laws.alike --write <파일>`로 만든 파일을 `tools.laws.apply`로 넣으며, 바뀐 문단은 검수 표시가 지워져 다시 읽힌다. 남은 묶음의 수는 `python -m tools.laws.status`가 알린다.
- 상태 점검(`tools/run/laws_health.py`)은 싣기로 한 문서를 원문 대장에서 찾지 못한 것, 절 나누기가 문서의 차례와 어긋난 것, 번역이 남았는데 여러 날 늘지 않은 것, 검수가 여러 날 늘지 않거나 일부러 바꾼 번역을 놓친 것, 번역과 검수가 맞선 문단이 생긴 것을 알린다. 검사에 걸려 남은 문단과 맞선 문단은 직전 보고 뒤에 생긴 것을 모두 센다(검수는 그날의 보고가 나간 뒤에 돌기 때문에, 그날 것만 세면 알림에서 빠진다).

### 용어집의 표기를 바꿀 때

표기의 기준은 `language/glossary.json`이다. 국내 공식기관이 쓰는 낱말을 먼저 고르고, 어디서 확인했는지를 그 낱말의 `note`에 적는다. 확인하지 못한 표기는 `status`를 `candidate`나 `partial`로 두고 무엇을 확인하지 못했는지 적는다. 표기를 바꾸면 그 낱말이 쓰인 곳을 한 번에 맞춘다.

- 번역(`data/laws-ko`): 원문에 그 영문이 나온 문단에서만 바꾼다. 같은 국문 낱말이 다른 영문을 옮긴 것일 수 있어서다(physical site의 '물리적 현장', single market의 '단일시장'은 그대로 둔다). 바꾼 글이 번역 검사(`tools.laws.check.problems`)에 새로 걸리지 않는지 보고 `tools.laws.store.sync`로 넣는다. 검수를 마친 문단은 '고친 뒤 다시 검수를 기다리는 것'으로 가고, 다시 검수하기 전에도 사이트에 실린다.
- 받침이 달라지는 낱말은 뒤의 조사까지 고친다('독립적인 사람이' → '독립된 자가': 이→가, 은→는, 을→를, 과→와, 으로→로, 이란→란, 이었→였). 낱말과 조사 사이에 닫는 따옴표, 괄호 풀이, 각주 표시가 끼어 있어도 조사를 본다(‘독립적인 사람’이란 → ‘독립된 자’란). 앞의 낱말을 받는 말도 함께 맞춘다('독립적인 사람의 자격 및 그 사람의 독립성' → '독립된 자의 자격 및 그 자의 독립성').
- 옛 표기를 용어집의 '쓰지 않는 표기'(`avoid`)로 올리면 그때부터 검사가 그 표기를 막는다. 규제 자료는 `tools.publish.rule_edit`가 고칠 때마다 전체를 검사하므로, 옛 표기가 여러 규제에 남아 있는 동안에는 그 표기에 `conditional`을 붙여 두고 규제를 모두 고친 뒤에 뗀다. 소식의 요약은 `tools.publish.revise --correct`로 고친다.
- 해설서, 규제, 의무 일정의 글(`data/handbook.json`, `data/regulations.json`, `data/duties.json`)과 사이트의 용어집(`data/terms.json`)을 함께 맞춘다. 용어집이 쓰지 말라는 표기가 이 글들에 남으면 검사(`tools.check.term_check`)가 잡는다.
- 번역 실행들이 적어 둔 낱말(`language/translation-terms.json`)에서 용어집에 들어간 것을 지운다(`python -m tools.laws.wording prune`).
- `data/laws-ko`에는 지금 화면에 쓰지 않는 옛 문단의 번역도 남아 있다(PDF 문서를 나누는 방식을 바꾸기 전의 문단. 단위 파일을 쓰지 못하게 되면 다시 쓰인다). 표기를 맞출 때 이 문단은 건드리지 않는다. 그래서 옛 표기를 파일에서 글자로 찾으면 이 문단들이 나온다. 지금 쓰는 문단인지는 `tools.laws.corpus.everything(history=True)`의 문단 열쇠로 가린다.

## 글 속 용어 풀이

소식 하나의 요약, 규제 하나의 글(현재 상황, 요약, 분석), 해설서의 문단과 목록에 나온 용어에는 점선 밑줄이 붙는다. 누르거나 마우스를 올리면 그 곁에 풀이 칸이 뜨고, 칸에는 용어의 이름(국문, 영문, 약어), 풀이, 해설서의 그 용어를 다루는 절과 용어집으로 가는 링크가 있다. CSCF 같은 약어를 글에서 만났을 때 그 자리에서 뜻을 보게 하려는 것이다.

- 표시하는 것: 해설서가 풀이한 용어(국문 표기와 약어), 입법 절차 화면이 풀이한 용어(일반입법절차, 3자 협상, 일반적 접근 같은 절차의 말. 풀이 칸이 그 화면의 해당 단계로 이어 준다), 용어집의 약어. 용어집의 국문 표기를 모두 표시하지 않는 까닭은 일상어와 겹치는 말이 많아서다. 무엇을 빼는지는 `sources/gloss.json`이 정한다(글마다 나오는 약어 CBAM·EU, 다른 말과 헷갈리는 두 글자 약어, 일상어로도 쓰는 국문 표기). 풀이는 해설서의 것을 앞세우고, 해설서에 없는 약어는 용어집의 풀이를 쓴다.
- 사이트를 만들 때 `tools/publish/gloss.py`가 `data/gloss.json`을 만든다. 같은 표기가 두 용어에 걸리면 해설서의 용어가 가진다. 빼라고 적은 말이 해설서나 용어집에 없으면 사이트 만들기가 멈춘다(자료가 낡은 것이다).
- 찾는 셈은 `site/js/gloss/match.js`다(node로 시험한다): 국문 표기는 띄어쓰기가 달라도 찾고, 영문 약어는 낱말 하나로 나온 곳만 대소문자를 가려 찾으며(복수형의 s는 받아 준다), 긴 표기부터 본다. 글 한 편(소식 하나, 규제 하나, 해설서의 절 하나)에서 용어마다 처음 나온 곳에만 표시한다. 해설서의 절은 그 절이 스스로 풀이한 용어를 건너뛴다.
- 화면은 그린 뒤에 표시를 붙인다(`site/js/ui/gloss.js`의 `gloss(화면, 고르는 말)`). 링크와 단추, 제목, 영문 원문에는 붙이지 않는다. 글자는 바꾸지 않으므로 찾기와 복사가 그대로 된다. 풀이 칸은 `site/js/ui/glosstip.js`, 모양은 `site/css/gloss.css`다. 누르거나 Enter로 열면 초점이 칸으로 가고, Esc나 칸 밖을 누르면 닫히며 초점이 용어로 돌아온다. 새 화면의 글에 붙이려면 그 화면을 그린 뒤 `gloss`를 부른다.
- 범위(`scope`): 같은 낱말이라도 제도마다 뜻이 다르다(영국 CBAM의 '회계기간'과 '인정기구', EU CBAM의 '과징금'과 '검증기관'). 해설서의 장에 `scope`가 적혀 있으면(영국 CBAM의 장은 `uk`) 그 장의 용어는 그 범위의 글에만 표시하고, 그 범위의 글에는 다른 용어를 표시하지 않는다. 그 범위의 글은 셋이다: 그 장, 이름이 같은 규제 묶음의 규제 화면, 그 묶음의 규제가 출처로 삼는 곳에서 온 소식(`data/gloss.json`의 `scopes`에 소식의 id로 실린다. 출처의 이름은 싣지 않는다). 낱말로만 이어진 소식은 넣지 않는다. 글의 범위는 `site/js/gloss/scope.js`가 가린다(node로 시험한다). 범위가 있는 용어의 풀이 칸은 해설서의 그 장으로만 잇는다(용어집은 EU CBAM의 용어다).
- 화면 점검의 `gloss` 검사(`tools/sitecheck/checks/gloss.mjs`)가 실제로 눌러 본다: 칸이 화면 안에 뜨는지, 자판으로 열고 닿는지, 닫은 뒤 초점이 돌아오는지. 범위가 있는 장에서는 풀이 칸의 링크가 그 장 안으로만 가는지도 본다.

## 품목 한 장 보기

품목 코드 조회(`#cn-<코드>`)에서 대상 품목을 찾으면 판정 아래에 그 품목의 '한 장 보기'가 놓인다. 방문자가 가장 먼저 묻는 것(내 품목은 대상인가, 값은 얼마인가, 무엇을 언제까지 하나, 근거는 어디인가)에 한 화면으로 답하려는 것이다.

- 놓는 것: 기본값(직접·간접·총배출량과 마크업을 더한 값)과 CBAM 벤치마크(생산경로와 연도 구간별 B열·A열), 인증서 비용의 어림(올해 수입분 제품 1톤, 해마다의 값), 다가오는 의무 일정, 근거 조문, 해설서의 절, 그 부문의 소식과 심의 중인 개정안. 8자리 코드로 품목 하나를 찾으면 자세히, 더 짧은 코드로 여러 품목을 찾으면 품목마다 한 줄로 보여 준다(누르면 그 품목의 한 장으로 간다). 값의 표가 없는 부문(전력)과, 표에 없는 코드에는 그 까닭을 적는다.
- 새로 적은 사실은 없다. 값과 비용은 인증서 비용 추정과 같은 자료, 같은 셈이고(`site/js/calc/compute.js`), 가정도 그 화면과 같은 말로 적는다. 일정은 의무 일정(`duties.json`), 소식과 개정안은 부문별 모아 보기의 자료(`sectors.json`)에서 온다.
- 근거 조문과 해설서의 절은 `sources/item-sheet.json`이 정한다(줄마다 무엇의 근거인지와 가리키는 곳, 그 줄을 보여 줄 품목 `when`: 직접배출량만 넣는 품목, 간접배출량도 넣는 품목, 값의 표가 있는 품목, 없는 부문의 품목). 사이트를 만들 때 `tools/publish/item_sheet.py`가 조문과 절의 이름을 규정 원문의 목록과 해설서에서 붙여 `data/sheet.json`에 싣고, 가리키는 곳이 없으면 사이트 만들기가 멈춘다.
- 셈은 `site/js/cn/sheet.js`(화면 요소를 다루지 않아 `tests/test_sitejs.py`가 node로 시험한다), 화면은 `site/js/views/cn/sheet.js`와 `views/cn/sheet/`(값 `values`, 비용 `cost`, 이어 가는 곳 `links`), 모양은 `site/css/cn-sheet.css`다. 자리의 너비에 따라 칸 수를 바꾼다. 비용 추정 화면의 고른 품목에서도 '이 품목 한 장 보기'로 온다.

## 역할별 준비 목록

준비 목록(`#prepare`, `#prepare-<역할>`, `#prepare-<역할>.<항목>`)은 "언제까지 무엇을 하나"에 역할마다 답하는 화면이다. 신고인·수입자, 제3국 사업자, 검증기관, 영국 수입자가 법령과 공식 안내에 따라 챙길 일을 묶음으로 나누어 차례로 놓고, 항목마다 해설서의 절, 근거 조문, 의무 일정, 사이트의 화면으로 잇는다. 주 메뉴의 '일정' 아래에 있다.

- 자료는 `data/prepare.json`이다(검사 `python -m tools.publish.prepare [만든 사이트의 data]`). 역할의 key와 이름은 의무 일정의 역할(`duties.json`의 `roles`)을 따른다. 항목은 해설서의 절(`from`)이나 의무 일정(`duty`)에 기대고, 일정에 기대는 항목은 제목과 글을 비워 두면 그 일정의 것을 쓴다(`note`로 '생산자가 준비할 것'이나 '검증기관이 알아 둘 것'을 고를 수 있다).
- 새로 적는 사실은 없다. 검사가 그것을 지킨다: 글에 적힌 날짜와 수가 그 항목이 기대는 절이나 일정의 글에 있어야 하고(날짜는 통째로, 수는 뒤의 한 글자까지 같아야 한다: "1월 1일"은 "11월 1일"로, "50톤"은 "150톤"으로 채워지지 않는다. '두 달', '네 번째'처럼 우리말로 적은 수도 본다. 묶음의 이름과 역할의 설명에 적힌 날짜와 수는 그 묶음, 그 역할의 항목들이 기대는 글에 있어야 하고, 소개와 알림에는 날짜와 수를 적지 않는다), 근거 조문(`refs`)은 기대는 절의 근거에 있는 것만 적을 수 있으며, 표기 규칙과 '권유·전망의 말이 없을 것'(규제 분석과 같은 기준)을 본다. 해설서나 의무 일정의 수가 바뀌면 이 목록의 글이 어긋난 것으로 잡혀 사이트 만들기가 멈춘다.
- 역할의 의무 일정은 모두 그 역할의 목록에 있어야 한다(시험 `tests/test_prepare.py`. 집행위원회가 하는 평가처럼 그 역할이 하는 일이 아닌 일정만 뺀다). 일정을 더하면 목록에도 더한다.
- 사이트를 만들 때 `tools/publish/prepare.py`가 절의 이름과 조문의 이름을 붙여 `data/prepare.json`으로 싣는다. 일정의 날짜와 글은 화면이 의무 일정에서 읽고, 해마다 돌아오는 의무는 다가오는 해의 일정을 고른다. 해마다 돌아오는 의무에 기대는 항목이 제 말로 적은 제목과 글은 첫 일정에 관한 것이다: 그 일정이 지나 다음 해의 일정으로 넘어가면 화면은 일정의 제목과 글을 쓴다(글은 첫해를 말하는데 날짜는 다음 해인 어긋남이 없게). 화면이 의무 일정을 읽지 못했을 때를 위해, 일정에 기대면서 제목이나 글을 비운 항목에는 그 일정의 제목과 글이 함께 실린다(`fallback`).
- 해설서의 '함께 보기'가 준비 목록의 역할이나 항목을 가리키면(`#prepare-<역할>.<항목>`) 해설서의 검사가 그곳이 실제로 있는지 본다(상태 점검도 같다). 항목의 id를 바꾸면 해설서의 링크도 함께 고친다.
- 셈은 `site/js/prepare/plan.js`(주소 읽기, 일정 고르기, 다가오는 날짜)와 `done.js`('확인함' 표시)이고 node로 시험한다. 화면은 `site/js/views/prepare.js`와 `views/prepare/`(항목 한 줄 `item`, 다가오는 날짜 `soon`), 모양은 `site/css/prepare.css`다.
- '확인함' 표시는 방문자의 브라우저에만 남는다(브라우저의 저장소, `cbam.prepare.done`). 사이트로 보내지 않고, 저장소를 쓸 수 없으면 화면을 떠날 때까지만 남는다. 표시를 적기 전에 저장소를 다시 읽으므로 다른 탭에서 한 표시를 덮어쓰지 않고, 목록에서 없어진 항목의 표시는 적을 때 거른다. 인쇄하면 고른 역할의 목록만 찍힌다.

## 부문별 모아 보기

사이트의 '품목·비용 > 부문별 보기'(`#sector-<부문>`: steel, aluminium, cement, fertilisers, hydrogen, electricity)는 부문 하나에 관한 것을 한 화면에 모은다: 대상 품목(CN 코드, 온실가스, 산정 범위), 그 부문의 EU 집행위원회 문서와 큰 절, 기본값·벤치마크가 정해진 품목 수와 마크업, 다가오는 의무 일정, 그 부문의 소식, 모든 부문에 함께 적용되는 문서.

- 무엇을 모을지는 `sources/sectors.json`이 정한다(부문마다 품목 목록의 부문 이름, 비용 추정 자료의 부문 이름, 문서의 id, 소식을 고르는 낱말과 그 낱말이 들어 있지만 다른 뜻인 말 `except`: 수소의 '탄화수소'). 사실을 적는 글은 이 파일에 두지 않는다.
- 화면의 수와 글은 모두 사이트의 다른 자료에서 만든다(`tools/publish/sectors.py` → `data/sectors.json`): 품목과 온실가스, 산정 범위는 품목 코드 조회의 목록(`cn.json`), 품목 수와 마크업은 인증서 비용 추정의 자료(`calc.json`), 문서의 이름과 차례는 규정 원문의 목록(`laws/index.json`), 소식은 제목·요약·다룬 내용에 그 부문의 낱말이 나온 것. 글로 풀어 쓰는 일은 `site/js/sector/facts.js`가 한다.
- 자료가 가리키는 부문이나 문서가 사이트의 자료에 없으면 사이트 만들기가 멈춘다(문서의 id가 바뀌었을 때 잡힌다).
- 기본값과 벤치마크(`#sector-<부문>.values`): 그 부문의 품목(8자리 CN 코드)마다 법령이 정한 내재배출량의 기본값(직접, 간접, 총배출)과 CBAM 벤치마크를 표로 보여 준다. 새로 적은 값은 없고 인증서 비용 추정의 자료(`calc.json`)를 줄로 편 것이다(`site/js/sector/values.js`, 화면은 `views/sector/values.js`). 표의 벤치마크는 기본값으로 신고할 때 쓰는 값(B열에서 기본값 표의 줄에 적힌 생산경로의 값)이고, 줄을 펼치면 기본값 표의 어느 줄인지, 마크업을 더한 값, 생산경로마다의 B열과 A열 값이 나온다. 코드의 앞자리나 품목 이름의 영문 낱말, 생산경로의 이름으로 찾을 수 있고, 표를 CSV 파일로 내려받을 수 있다(품목과 생산경로마다 한 줄). 값의 표가 없는 전력 부문에는 기본값이 나라마다 정해져 있다는 것과 그 부속서로 가는 링크만 둔다(나라별 전력 배출계수는 국제에너지기구의 자료여서 옮겨 싣지 않는다).

## CBAM 해설서

사이트의 '해설서'(`#handbook`, `#handbook-<장>`, `#handbook-<장>.<절>`)는 제도가 돌아가는 차례를 장과 절로 풀어 쓴 글이다. CBAM을 처음 맡은 사람이 읽는 글이므로 소식처럼 날마다 바뀌는 것은 싣지 않고, 법령이 정한 오래가는 규칙만 적는다. 진행 중인 개정이나 지금의 가격은 그 화면으로 잇는다.

- 글은 `data/handbook.json`에 손으로 적는다. 꼴은 `tools/publish/handbook.py`의 머리 설명에 있다: 장(`chapters`) 아래에 절(`sections`)이 있고, 절에는 문단(`body`)과 필요할 때 목록(`list`, 차례가 있으면 `ordered`), 식(`formula`), 표(`table`), 그 절에서 처음 나오는 용어의 풀이(`terms`), 알아 둘 점(`caveat`), 관련 화면(`see`)을 둔다.
- 그림(`figure`): 절의 글을 한눈에 보이게 한 것이다. 그림 파일을 두지 않고, 자료에 적은 내용을 화면이 그린다(차례 `flow`, 때의 흐름 `timeline`, 칸의 묶음 `tiles`, 넣는지 아닌지의 표 `matrix`, 두 쪽이 하는 일 `lanes`, 셈의 틀 `equation`, 묶음별 막대 `bars`, 전체를 몫으로 나눈 막대 `split`, CBAM 계수의 연도별 값 `factor`). 꼴은 `tools/publish/handbook_figures.py`의 머리 설명에 있다. 그림에는 그 절의 글과 표에 있는 사실만 적는다: 그림의 수와 날짜가 절의 글에 있는지, 다른 참고 자료(마크업, 계산 예, 품목 목록의 '직접배출량만', 일정의 의무)와 맞는지를 시험이 본다. 식(`formula`)의 한 줄도 풀이가 달린 말을 칸으로 그린다. 화면은 `site/js/views/handbook/figure.js`와 `views/handbook/figures/`(종류마다 한 파일), 모양은 `site/css/handbook-figures.css`다. 넓은 자리에서는 가로로, 좁은 자리에서는 세로로 놓인다. 화면 점검은 그림의 종류가 모두 한 번씩 보이도록 장을 골라 본다(`tools/sitecheck/plan.mjs`의 `figureChapters`).
- 그림의 자리(`after`): 그림은 문단을 모두 놓은 뒤에 놓는다. 마지막 문단이 목록을 가리키는데 그림이 그 목록의 그림이 아니면, 그림에 `after`(그림 앞에 오는 문단의 수)를 적어 그 문단 앞으로 올린다. 칸이 셋 이상이고 글이 긴 표는 좁은 화면에서 줄마다 한 칸으로 쌓아 보여 준다(`views/handbook/section.js`의 `sheet`).
- 절마다 근거(`basis`)를 적는다. 사이트의 규정 원문에 있는 문서이면 문서와 조각(`act`, `part`)을, 그 밖의 문서(EU 배출권거래제 지침, 영국의 법령)이면 `sources`에 적어 둔 이름(`source`)을 가리키고, 그 절의 사실이 적힌 영문 대목을 원문 그대로 `contains`에 옮겨 적는다. 그 밖의 문서는 주소가 하나이므로 화면은 문서마다 한 번만 잇고 그 문서에 댄 조와 항을 링크 뒤에 글로 적는다(`sources`의 `short`가 링크의 이름이 된다). 수, 날짜, 누가 무엇을 해야 하는지마다 대목 하나씩이다. 법령과 가이던스가 다르면 법령을 따르고, 가이던스나 전문(recital)에만 있는 말은 글에서 그렇다고 밝힌다.
- 검사(`python -m tools.publish.handbook --laws <만든 사이트의 data/laws>`): 높임말과 표기, 용어집이 쓰지 말라는 표기, 같은 용어를 두 번 풀이하지 않았는지, 링크가 가리키는 곳(규정 원문의 조각, 규제 화면, 해설서의 장과 절)이 실제로 있는지, 목록을 가리키는 문장('아래 …', '다음 …')이 본문의 마지막 문단에 있는지를 본다(화면은 목록을 문단 뒤에 놓는다). 어긋나면 사이트 만들기가 멈춘다. 근거로 적은 대목이 원문에 없으면 '근거 어긋남'으로 알리기만 한다(원문이 개정된 것일 수 있다). 상태 점검(`tools/run/reference_health.py`)이 받아 둔 법령의 글과 날마다 대조해 일일 보고에 올린다. 그때는 그 절을 원문과 다시 맞춰 보고 글과 대목을 고친다.
- 다른 참고 자료와 겹치는 수치(CBAM 계수, 마크업, 부문 간 보정계수, 계산 예의 값)는 시험이 그 자료와 견준다(`tests/test_handbook.py`). 자료가 바뀌면 시험이 해설서의 어느 절을 고쳐야 하는지 알려 준다.
- 다른 화면에서 해설서로 돌아오는 길: 해설서의 절이 스스로 적어 둔 근거 조문, 풀이한 용어, 관련 화면을 뒤집어 `data/refs.json`에 싣는다(`tools/publish/crossrefs.py`). 규정 원문의 조에는 '이 조와 이어진 내용'에 그 조를 근거로 든 절이, 용어집의 용어에는 그 용어를 풀이한 절이, 규제 화면에는 그 규제를 가리킨 절이 보인다. 새로 어림해 잇는 것은 없다.
- 가리킨 규제가 달라졌을 때: 해설서에는 절이 관련 화면으로 가리킨 규제의 모습(단계, 연혁의 줄 수)을 맞춰 본 때의 것으로 적어 둔다(`rulesSeen`). 규제 자료가 이 기록과 달라지면 상태 점검이 '해설서에서 다시 볼 절'로 일일 보고에 올린다(`tools/publish/handbook_rules.py`, 문제로 세지 않는다). 그 절을 규제 자료와 원문에 맞춰 다시 읽고(고칠 것이 있으면 고친 뒤) `python -m tools.publish.handbook_rules --accept`로 기록을 고친다. 주간 작업이 주마다 다시 본다: 그 절을 규제의 지금 모습과 견줘 읽고, 고칠 것이 없는 규제만 `--accept <규제 id>`로 넘기며, 글을 고쳐야 하는 규제는 주간 보고에 적고 남겨 둔다(해설서의 글은 예약 실행이 고치지 않는다).
- 전체 보기와 인쇄: `#handbook-all`은 해설서 전체를 한 화면에 놓는다(`views/handbook/whole.js`). 인쇄하면 머리글과 옆의 목록, 단추가 빠지고 장마다 새 쪽에서 시작한다(`site/css/handbook-print.css`). 장 하나의 화면을 인쇄해도 같은 모양이다. 장의 id로 `all`은 쓰지 않는다.
- 공개용 사본(`data/handbook.json` → 사이트의 `data/handbook.json`)에서는 대조용 대목과 저장소 안의 경로를 빼고, 근거마다 이름을 붙인다. 화면은 `site/js/views/handbook.js`와 `views/handbook/`(차례 `contents`, 장 `chapter`, 절 `section`), 모양은 `site/css/handbook.css`다. 절은 사이트 검색의 한 갈래로도 찾는다.
- 영국 CBAM의 장(`uk`, 13장): 2026년 재정법 제5편과 부칙 17·18·19, 하위 법령 다섯 건(SI 2026/802, 809, 830, 994, 995)의 받아 둔 글(`collected/archive/pages/uk-legislation/`)에 따라 적었다. 법령에 없는 것(등록이 열리는 날, 게시된 고시와 안내 문서의 게시일)은 받아 둔 영국 국세청 안내의 갱신 기록(`collected/archive/pages/uk-govuk/changes.txt`)에 대고, 그 문장에 영국 국세청의 안내라고 밝힌다(시험이 본다). 사이트의 규정 원문에 없는 문서라서 근거는 모두 `sources`에 적고 받아 둔 글과 대조한다(상태 점검이 날마다 본다). 영국 법률의 Schedule은 규제 자료와 같이 '부칙'으로 적는다. 고시(notice)와 시스템 경계 문서, 부칙 16의 품목 코드 표는 받아 두지 않아 다루지 않고, 그렇다고 절의 '알아 둘 점'에 적었다. 장에 `scope: "uk"`가 있어 그 장의 용어 풀이는 영국 CBAM을 다루는 글에서만 쓰이고(위 '글 속 용어 풀이'), 용어집에서 해설서로 돌아오는 길에는 싣지 않는다. 날짜(기록 보관의 시작, 등록이 열리는 날, 등록 기한, 첫 세 회계기간의 신고와 납부 기한)는 시험이 일정 화면의 영국 의무와 견준다. 시행일처럼 날이 지나면 틀리게 되는 말("시행됩니다")은 쓰지 않고 "시행일은 …입니다"로 적는다.
- 글을 고치거나 장을 더할 때: 원문에서 확인한 사실만 적는다. 문장은 짧게, 높임말로 쓰고, 용어는 용어집의 표기를 쓴다(전문용어는 절에서 처음 나올 때 영문을 괄호로 붙인다). 전망, 평가, 권유는 쓰지 않는다. 아직 정해지지 않았거나 바뀔 수 있는 것은 `caveat`에 적고 그 규제의 화면으로 잇는다.

## 사이트 검색과 메뉴

머리글의 검색 칸에 찾는 말을 적으면 검색 화면(`#search-<찾는 말>`)이 용어집, 해설서, 규제, 소식, 일정, 품목 코드, 원문 대장, 규정 원문에서 한 번에 찾아 갈래별로 보여 준다. `/` 키를 누르면 검색 칸으로 간다. 좁은 화면에서는 칸 대신 돋보기 단추가 검색 화면을 연다.

- 낱말을 읽고 점수를 매기는 일은 규정 원문의 찾기 엔진(`site/js/laws/engine.js`)이 한다. 그래서 용어집의 낱말은 국문으로 적어도 영문 표기까지 함께 찾는다(예: '기본값'으로 'default value'가 든 문서 이름과 조문).
- 게시 데이터의 기록을 찾기 좋은 줄로 바꾸는 일은 `site/js/search/rows.js`, 갈래마다 찾고 걸러 내는 일은 `find.js`, 화면으로 바로 가는 길은 `pages.js`, 품목 코드 읽기는 `codes.js`가 한다. 모두 화면 요소를 다루지 않아 node로 시험한다(`tests/test_search.py`). 화면은 `site/js/views/search.js`와 `views/search/`, 머리글의 칸은 `site/js/ui/sitesearch.js`다.
- 낱말이 여럿이면 함께 나온 곳만 보여 준다(둘까지는 모두, 셋부터는 하나가 빠져도 된다). 그런 곳이 어디에도 없을 때에만 낱말의 일부가 나온 곳으로 물러서고, 화면이 그렇다고 밝힌다.
- 찾는 말이 CN 코드이면(예: `7208`, `CN 7318 15`) 품목 코드 조회와 같은 셈으로 가린 판정을 맨 위에 보여 주고, 글에서는 그 코드를 낱말 하나로 찾는다(붙여 쓴 꼴과 띄어 쓴 꼴). 목록에 없는 네 자리 숫자는 연도일 수 있어 코드로 보지 않는다.
- 짧은 영문 낱말과 숫자는 다른 낱말 속에 든 것을 찾은 것으로 보지 않는다. 세 글자까지의 약어(ETS, CEM)는 낱말 하나로 나온 곳만(markets, cement에 걸리지 않게), 그 밖의 세 글자까지의 낱말은 낱말의 첫머리에서만, 숫자는 그 숫자 하나로 나온 곳만 찾는다. 두 글자 약어와 흔한 낱말과 글자가 같은 약어(SEE, BAT)는 대문자로 적었을 때만 약어로 읽고, 질문에서 용어집의 영문 표기를 읽을 때에도 낱말의 첫머리부터 맞아야 한다(neutral의 eu를 EU로 읽지 않는다). 규정 원문의 찾기에도 같은 기준이 쓰인다.
- 결과를 누르면 그 자리로 간다: 해설서는 그 절로 가고(`#handbook-<장>.<절>`), 용어집과 원문 대장은 그 말로 걸러 보여 주고(`#terms-<말>`, `#docs-<말>`), 일정은 그 일정으로 옮겨 가 잠깐 표시한다(`#calendar-<해>.<일정의 번호>`). 소식의 출처 이름은 찾는 글에도 결과에도 넣지 않는다.
- 규정 원문의 글은 크므로 다른 갈래를 먼저 보여 주고 나서 읽어 더한다.

화면과 그 묶음은 표 하나(`site/js/nav/map.js`)에 적는다. 머리글의 주 메뉴와 펼침 목록, 화면 안의 탭, 전체 메뉴, 바닥 메뉴, 안내 화면, 검색의 '화면으로 바로 가기'가 모두 이 표를 따른다.

- 주 메뉴는 일곱 묶음이다: 최신 동향, 소식, 규제(규제, 입법 절차), 일정, 품목·비용(품목 코드 조회, 부문별 보기, 인증서 가격, 비용 추정), 해설서(해설서, 용어집, 안내), 원문·자료(규정 원문, 원문 대장). 묶음의 첫 화면이 메뉴를 눌렀을 때 열리는 화면이고, 묶인 화면들은 화면 머리의 탭(`site/js/ui/tabs.js`의 `groupTabs`)으로 오간다.
- 화면을 더하거나 묶음을 바꿀 때에는 표를 고치고, `site/index.html`의 주 메뉴와 바닥 메뉴(처음 그릴 때 깜박이지 않게 적어 둔 것)를 맞춘다. 표와 어긋나면 시험이 알린다(`tests/test_nav.py`: 메뉴의 차례와 이름, 바닥 메뉴, 주소로 갈 수 있는 화면, 탭을 그리는 화면, 아이콘).
- 펼침 목록: 주 메뉴에 마우스를 올리면 그 메뉴 아래의 목록이 펼쳐진다(소식의 주제, 규제의 묶음, 일정이 있는 해, 묶인 화면들). 마우스가 없는 기기와 자판을 위해 메뉴 옆에 펼침 단추가 있고, 메뉴에서 아래 화살표 키를 눌러도 펼쳐진다. 메뉴가 둘째 줄로 내려가는 너비(1000px까지)에서는 쓰지 않는다. 목록의 내용은 게시 데이터를 따른다: 주제는 `data/topics.json`, 규제 묶음과 일정이 있는 해, 소식이 있는 주제, 해설서의 장은 사이트 폴더를 만들 때 `site.json`의 `menu`에 실린다(`tools/publish/derive.py`의 `menu`). 화면은 `site/js/ui/navmenu.js`와 `site/css/navmenu.css`다.
- 전체 메뉴: 머리글 오른쪽 끝의 단추가 모든 화면과 그 안에서 고를 수 있는 것(주제, 규제 묶음, 해, 해설서의 장)을 한 창에 펼쳐 보여 준다(`site/js/ui/allmenu.js`). 펼침 목록을 쓰지 않는 폰과 패드에서는 이 창이 모든 화면으로 가는 길이다. 폰에서는 주 메뉴에서 '최신 동향'을 빼고(이름표가 같은 화면으로 간다) 나머지 여섯 묶음을 한 줄에 보여 준다.
- 첫 화면의 길잡이(`site/js/views/home/start.js`): 큰 머리 바로 아래에서 처음 온 사람에게 네 갈래(해설서, 품목 코드 조회, 비용 추정, 일정)와 전체 메뉴를 알려 준다. '접기'를 누르면 그 브라우저에서는 다시 보이지 않는다.

### 없는 주소, 규제 변화 기록, 이름

- 없는 주소: 화면의 이름이 아닌 주소(`#rule`, `#glossary`)는 안내 화면으로 간다(`site/js/router.js`의 `route`, `site/js/views/missing.js`). 주소의 첫 낱말을 화면의 이름과 그 화면을 찾을 때 쓸 만한 말에 견줘 찾으려던 화면을 어림해 보여 주고(`site/js/nav/guess.js`), 검색 칸과 모든 화면을 함께 둔다. 사이트에 없는 경로(`/cbam-watch/아무 이름`)에서는 GitHub Pages가 `site/404.html`을 보여 준다. 어느 깊이의 경로에서도 열리므로 링크를 사이트의 온전한 주소로 적었고, 경로가 화면의 이름처럼 생겼으면 사이트의 그 주소로 넘긴다.
- 규제 변화 기록(`#rules-recent`, `#rules-recent-90`): 규제마다 적어 둔 연혁을 합쳐 최근 30일·90일에 달라진 것만 날짜가 늦은 것부터 보여 준다(`site/js/rules/changes.js`가 고르고 `site/js/views/rules/recent.js`가 그린다). 날짜는 그 일이 일어난 날이다. 규제 전체 화면에는 가장 최근의 네 줄을 '곧 움직일 규제' 옆에 싣는다. 자료를 따로 만들지 않는다(화면이 `regulations.json`의 연혁에서 고른다). 규제와 묶음의 이름은 `recent`로 시작할 수 없다(시험이 본다). 왼쪽 고르기의 '최근 변화'에는 변화 기록을 보고 있으면 보고 있는 날수의 건수와 주소를, 다른 화면에서는 30일의 것을 적는다(`sidePeriod`. 고른 표시가 붙은 칸의 건수가 본문의 건수와 같아야 한다).
- 조의 달라진 곳: 규정 원문의 조와 부속서 머리에, 앞선 판과 견줘 그 조각에서 달라진 문단이 있으면 '달라진 곳 N곳' 링크가 붙는다(`tools/laws/revisions.py`의 `brief`가 조각마다의 수를 싣는다). 달라진 곳 화면은 주소에 조각을 적으면 그 조각으로 간다(`#changes-<문서>.<조각>`, 지난 대조는 `#changes-<문서>.<몇 번째>.<조각>`). 차례에서 조각을 고르면 화면을 다시 그리지 않고 주소만 그 조각의 것으로 바꿔 둔다.
- 조각을 적은 주소와 뒤로 가기: 조각을 적은 주소(`#law-….art-7`, `#handbook-….<절>`, `#changes-….art-7`)는 뒤로·앞으로 가기로 돌아왔을 때에도 그 조각에서 시작한다(다른 화면은 보던 자리로 돌아간다). 세 화면 모두 차례에서 조각을 고르면 주소를 그 조각의 것으로 바꿔 두므로, 돌아오면 마지막에 고른 조각이 보인다.
- 용어집의 '쓰인 곳': 용어마다 그 국문 표기로 사이트 검색을 여는 링크를 단다(표준의 이름처럼 긴 표기는 영문 표기로 찾는다).
- 첫 화면의 차례(`site/js/news/lead.js`): 맨 위의 '새 소식' 한 줄과 '최근 소식'의 카드는 최근 30일의 소식 가운데 중요도가 보통 이상인 것을 날짜 차례로 먼저 놓고, 낮은 것을 그 뒤에 놓는다. 소식 화면의 차례는 바꾸지 않는다.
- 중요도의 이름(`site/js/news/importance.js`): 자료의 값은 높음·보통·낮음이고, 가장 높은 것은 화면에 '중요'로 적는다. 카드의 표시와 소식 화면의 조건이 이 한곳의 이름을 쓴다.
- 출처의 이름(`sources/labels.json`, `tools/publish/source_names.py`): 출처 대장의 이름은 운영에 쓰는 이름이라 영문 화면 이름이 섞여 있다. 화면에는 국문 이름을 적는다. 저장소의 자료는 고치지 않고, 사이트를 만들 때 자료를 읽자마자 바꾼다(소식, 일정, 가격, 원문 대장의 묶음 이름이 모두 바꾼 이름을 쓴다). 대장에 영문 이름의 출처를 더하면 이 파일에도 적는다(시험이 알린다).
- 원문 대장의 국문 이름: 번역해 '규정 원문'에 실은 문서에는 국문 이름을 함께 적고 '원문과 국문 번역 보기'로 그 화면에 잇는다(`tools/publish/derive.py`의 `translated`). 문서 찾기는 국문 이름으로도 된다.

## 화면 점검

`tools/sitecheck`는 만든 사이트를 브라우저(이미 깔려 있는 크롬)로 열어 검사한다. 화면 파일이나 게시 데이터가 바뀌면 워크플로 '화면 점검'(`.github/workflows/sitecheck.yml`)이 돌린다. 사이트 배포는 이 검사를 기다리지 않고, 문제가 나오면 '운영 보고' 이슈에 어느 화면이 왜 걸렸는지 적힌다(`python -m tools.notify.run --event sitecheck`).

- `layout`: 모든 화면을 일곱 너비(360~2400. 넓은 모니터의 두 단계인 1920과 2400도 본다)로, 규제 화면을 규제마다 네 너비로 열어 가로 넘침, 화면 밖으로 나간 글, 그려지지 않은 화면, 본문에 찍힌 깨진 값(undefined, NaN), 화면 오류와 받지 못한 파일을 본다.
- `axe`: 주요 화면에 접근성 자동 검사(axe-core)를 색 변형 셋, 너비 둘로 돌린다. 이 사이트에서는 위반이 아닌 것 하나를 가려낸다(`checks/axe_rules.mjs`): 좁은 화면에서 가로로 넘겨 보는 고르기 줄(`.side-nav`)은 고른 것이 보이도록 옮겨 두는데(`site/js/ui/sidenav.js`), axe가 화면 왼쪽 밖에 놓인 그 줄의 링크를 건너뛰기 링크로 본다. 그 줄 안의 것만 세지 않고, 진짜 건너뛰기 링크는 그대로 검사한다. 그 줄 안의 요소인지는 화면에서 요소의 윗자리로 가린다(axe가 적어 주는 고르는 말에는 윗자리가 빠질 수 있어 글자로 가리지 않는다).
- `calc`: 인증서 비용 추정 화면을 실제로 다뤄 본다(품목 찾기와 고르기, 신고 방법과 연도 바꾸기, 전구물질과 탄소가격 넣기, 초점이 제자리로 가는지, 결과에 깨진 값이 없는지, 다른 화면에 다녀와도 넣은 값이 남는지, '처음부터 다시'). 폰과 노트북, 넣는 칸이 따로 밀리는 넓은 화면(1920px)에서 본다.
- 화면의 목록은 만든 사이트의 데이터에서 뽑으므로(`plan.mjs`) 규제나 주제가 늘어도 따라간다.
- 손으로 돌리기: `python3 -m tools.publish.build_site /tmp/_site && npm ci --prefix tools/sitecheck && node tools/sitecheck/run.mjs /tmp/_site` (일부만 돌리려면 `--only layout,axe,calc`, 결과 파일은 `--report <파일>`). 크롬이 다른 곳에 있으면 `CHROME_PATH`에 적는다.
- 고친 화면을 눈으로 볼 때는 `node tools/dev/shot.mjs <사이트 폴더> "<#화면>@<너비>[:<높이>]=<그림 파일>[!<누를 요소>]"`로 그림을 찍는다(가로 넘침과 화면 오류도 함께 알려 준다).

## 지난 소식 채우기

사이트를 연 날보다 앞선 소식(2025년 1월부터)은 평소의 자동 실행과 따로 한 번에 채웠습니다. 같은 일을 다시 할 때의 차례입니다.

1. 모으기. 워크플로 '소급 수집'(`.github/workflows/archive.yml`)을 손으로 돌립니다. `mode`를 `crawl`로 두고 `steps`에 출처 이름을 띄어 적으면 그 출처만 돕니다(비우면 모두). 결과는 `collected/archive/`에 쌓입니다. 출처마다 목록(`<출처>.json`), 재이용이 허용된 자료의 원문 글(`pages/`), 실행 결과(`report/`)가 있습니다.
   - `ec-news`: EU 집행위원회 조세·관세총국 소식. 사이트 지도에서 소식 주소를 얻어 본문에 CBAM이 나오는 것만 남깁니다.
   - `ec-newsletter`: EU 집행위원회가 보내는 CBAM Newsletter의 보관함. `eur-lex`: CBAM 법령의 제목, 채택일, 관보 게재일, 시행과 적용에 관한 조문(EU 출판국의 자료 창구에서 받습니다).
   - `ep-oeil`: 유럽의회 입법 관측소의 절차 기록. `ec-hys`: 의견수렴 목록. `uk-govuk`: 영국 정부 CBAM 문서의 변경 기록.
   - `kr-boards`: 국내 기관 게시판의 제목, 날짜, 주소. 본문은 받아 두지 않습니다(산업통상부 보도자료만 부제와 첫 문단을 짧게 남깁니다).
2. 쓰기. 모아 둔 글을 읽고 국문 초안을 만듭니다. 초안 파일은 저장소에 올리지 않습니다.
3. 싣기. `python3 -m tools.archive.publish --drafts <초안 파일> [--dry-run]`. 형식, 문체, 용어, 원문 대조(수치와 날짜, 게시일), 링크, 원문 발췌를 검사해 통과한 것만 `data/items.json`에 더하고 `backfill` 표시를 붙입니다. 이 표시가 있는 소식은 원문이 그 주에 나온 것이 아니면 주간 요약의 대상에서 빠지고(`tools/run/week_items.py`), 주간 작업이 주마다 10건씩 원문과 다시 대조합니다.

제목만 옮겨 실은 소식. 국내 기관 게시판의 지난 글은 본문을 받아 두지 않아 제목만으로 한 문장을 썼습니다. 이런 소식에는 `brief` 표시가 있고 사이트에서 요약 없이 한 줄로 보입니다. 소식의 기본 목록과 건수, 최신 동향에서는 빼고 '국내 공지·자료'(`#news-notices`)에 달마다 모아 보여 줍니다(`site/js/news/notices.js`). 최신 동향의 '최근 30일 소식' 칸은 센 것과 같은 소식만 보이는 `#news-recent`로 갑니다. 날수와 가리는 법은 `site/js/news/recent.js` 한곳에 있고, 소식 화면의 '기간' 조건(최근 30일, 최근 90일, 연도)도 같은 법을 씁니다. 원문을 읽고 요약을 쓴 뒤 `python3 -m tools.publish.revise`로 바꾸면(문체, 용어, 길이, 수치와 날짜를 검사합니다) 표시가 떨어지고 카드로 보입니다. 쓰는 법은 그 파일 머리에 있습니다.

## 사이트의 디자인

- 방향: 짙은 남색의 큰 머리(점 지도, 지금 알아 둘 수치 세 칸)와 밝은 본문에 유리 면(글래스모피즘)을 입혔습니다. 단추는 알약 모양입니다. 값은 모두 `site/css/tokens.css`에 있습니다.
- 유리 면: 본문 뒤에는 화면에 붙박인 빛의 바탕(`--field`: 네 귀퉁이에서 번지는 파랑, 노랑, 하늘빛, 보라)을 깔고, 판과 카드는 반투명한 면(`--pane`, 그 안의 작은 칸과 단추·입력 칸은 더 불투명한 `--pane-2`)에 밝은 테두리(`--pane-line`)와 위쪽 가장자리의 빛(`--shadow-1`에 든 안쪽 선)을 둡니다. 뒤로 내용이 지나가는 면(머리글, 붙어 있는 도구 줄, 펼침 목록, 작은 창, 용어 풀이, 맨 위로 가는 단추)은 뒤를 흐리게 합니다(`--frost-bg`, `--frost`). 화면 전체에 걸친 꾸밈은 `site/css/glass.css`에 있고, 판마다 어느 면을 쓰는지는 저마다의 꾸밈 파일에 있습니다.
  - 불투명해야 하는 것은 그대로 `--surface`를 씁니다: 선을 가리는 점과 이름표(일정선의 판은 그래서 비치지 않습니다), 빛깔을 섞어 만드는 바탕.
  - 머리글은 화면 맨 위에 있을 때는 제 빛깔 그대로이고(`--head-rest`) 내려가기 시작하면 유리가 됩니다. 머리글의 유리 면은 뒤에 깐 한 겹(`.site-head::before`)에 둡니다. 머리글 자체가 뒤를 흐리게 하면 그 안에서 펼쳐지는 목록이 본문을 흐리게 하지 못하기 때문입니다.
  - 글자의 대비: 빛이 짙은 곳일수록 그 위의 글자가 덜 또렷해집니다. 브라우저의 자동 검사는 빛의 바탕을 보지 못하므로(바탕색만 봅니다) `python3 -m tools.art.glass`가 빛이 가장 짙은 곳에서의 대비를 직접 셈하고, `tests/test_glass.py`가 색 변형마다 4.5:1을 지키는지 봅니다(빛의 바탕 위의 글자, 판 위의 글자, 뒤로 짙은 면이나 흰 면이 지나갈 때의 흐린 면과 머리글). 빛의 세기나 면의 투명도를 올리려면 이 시험이 통과하는 데까지만 올립니다.
  - 뒤를 흐리게 하지 못하는 브라우저에서는 그 면들이 불투명한 면이 되고, 운영체제에서 '투명도 줄이기'를 켠 기기에서는 모든 유리 면이 불투명해지고 빛의 바탕이 걷힙니다(`themes.css`의 끝).
- 색은 EU 깃발의 파랑(#003399)과 노랑(#FFCC00)을 빌렸습니다. 깃발(별 열두 개)과 EU 기관의 로고는 쓰지 않습니다. 개인이 운영하는 비공식 사이트입니다.
- 글꼴은 Pretendard 하나입니다.
- 폭: 본문은 1,160px이고, 넓은 모니터에서는 세 단계로 넓어집니다(화면 폭 1500px부터 1,320, 1800px부터 1,560, 2200px부터 1,800. `site/css/layout.css`). 넓어진 폭은 글줄을 늘이는 데 쓰지 않고 칸을 늘리는 데 씁니다: 목록은 칸 수를 더하고, 넣는 칸과 결과가 있는 화면(비용 추정, 인증서 가격, 품목 코드 조회)은 둘로 나눕니다. 비용 추정의 넣는 칸은 화면 높이까지만 차지하고 그 안에서 밀어 보므로, 값을 고치는 동안 결과가 옆에 보입니다. 그 규칙은 모두 `site/css/wide.css`에 있고, 노트북과 패드, 폰에서는 걸리지 않습니다.
- 이름표는 글자입니다: 'CBAM' 뒤에 노란 세로선(국경선)과 '규제동향'. 네모난 표지(`site/assets/favicon.svg`, CB와 AM 사이에 노란 선)는 탭 아이콘에만 씁니다.
- 첫 화면(`site/js/views/home.js`가 `home/` 폴더의 칸들을 차례로 놓습니다): 큰 머리(`hero`, `facts`. 수치 칸 위에 새 소식 한 줄), 처음 온 사람을 위한 길잡이(`start`), 가장 최근의 요약(`digest`. 기간에 따라 '이번 주 요약', '지난주 요약', '주간 요약'으로 부르고, 여러 주를 묶은 요약은 '최근 동향 요약'이라고 부릅니다), 가장 중요한 소식(`feature`), 다가오는 일정·인증서 가격 추세·주제별 소식·규제 진행 상황(`panels`), 품목 코드 조회(`lookup`), 최근 소식, 품목별 가이던스(`sectors`).
- 점 지도(`site/js/ui/heromap.js`)는 두 장을 겹친 것입니다. 아래 장은 유럽에서 동아시아까지를 점으로 찍은 지도(EU 회원국은 밝게, 한국은 노랗게)이고, 위 장은 부산에서 말라카 해협과 수에즈 운하를 지나 EU의 항구 다섯 곳(피레우스, 코페르, 발렌시아, 르아브르, 로테르담)으로 가는 뱃길입니다. 뱃길은 화면이 열릴 때 부산에서 EU 쪽으로 한 번 그려지고(가지는 줄기가 갈라지는 곳에 닿을 때), 그 뒤로는 작은 빛이 같은 쪽으로 천천히 지나갑니다(움직임을 줄이도록 설정한 기기에서는 다 그려진 채로 멈춘 그림). 뱃길은 실제 항로를 그대로 옮긴 것이 아니라 점 사이로 지나가게 잡은 약도입니다. 지도 위와 아래에는 이름이나 설명글을 두지 않습니다(무엇을 그린 것인지는 화면 낭독기용 글에만 적혀 있습니다). 그림 안의 꾸밈은 `site/css/map.css`, 놓는 자리는 `layout.css`에 있고, 화면 머리 띠에는 같은 그림에서 유럽 언저리만 크게 깔아 둡니다(뱃길과 한국의 점은 감춥니다).
- 움직임은 `site/css/motion.css`와 `site/js/ui/motion.js`에 모아 두었습니다. 본문의 칸은 화면에 들어올 때 한 번 차례로 올라오고, 가격 그림의 선과 규제 단계의 선은 그때 그려지며, 큰 수치는 올라갑니다(`ui/countup.js`). 지금 진행 중인 것(갱신 시각, 진행 중인 규제, 지금 가격, 일정선의 오늘)은 점이 천천히 번집니다. 첫 화면의 큰 머리에는 가장 최근 소식의 제목이 한 줄씩 돌아가고(`ui/ticker.js`), 품목 코드 조회 칸의 예시가 번갈아 바뀌며(`ui/typehint.js`), 주 메뉴의 밑줄은 메뉴 사이를 미끄러져 옮겨 갑니다(`ui/navink.js`). 긴 글 화면(규제 하나)에서는 머리글 아래에 읽은 만큼 선이 차고, 한참 내려오면 맨 위로 가는 단추가 보입니다(`ui/scrollcue.js`). 움직임을 줄이도록 설정한 기기에서는 모두 멈추고 아무것도 숨기지 않습니다. 새로 만든 칸이 화면에 들어올 때 나타나게 하려면 `ui/motion.js`의 목록에 그 칸의 이름을 더합니다.
- 소식의 제목이나 미리보기 그림을 누르면 원문으로 가기 전에 국문 요약 화면(`#item-<소식 번호>`, `site/js/views/item.js`)을 먼저 보여 줍니다. 제목이 곧 내용인 한 줄 소식만 원문으로 바로 갑니다(`site/js/ui/itemlink.js`). 뒤로 가면 보던 자리로 돌아옵니다(`site/js/router.js`).
- 닫아 둔 기능: 새 소식 받아 보기(구독 피드와 안내 창, `site/js/ui/subscribe.js`, `tools/publish/feed.py`)와 의견 보내기(`site/js/ui/feedback.js`)는 만들어 두었지만 지금은 닫혀 있습니다. `site/site.config.json`의 `features`에서 `subscribe`, `feedback`을 `true`로 바꾸면 다시 열립니다. 닫혀 있는 동안에는 화면에 단추가 없고 구독 피드 파일(`feed.xml`, `rules.xml`)도 만들지 않습니다.
- 색 변형은 세 가지입니다: 네이비(기본), 화이트, 미드나잇. 주소에 `?theme=white`처럼 붙이면 바꿔 볼 수 있고, 기본값은 `site/js/theme.js`의 `DEFAULT`입니다. 변형마다 달라지는 값은 `site/css/themes.css`에만 있습니다.
- CSS는 쓰임새로 나눴습니다: 값(`tokens`), 바탕(`base`), 틀과 큰 머리(`layout`), 지도 그림(`map`), 유리 면의 바탕과 흐린 면(`glass`), 여러 화면이 함께 쓰는 부품(`components`), 첫 화면(`home`), 소식 요약 화면(`item`), 뜨는 창과 여백의 탭(`overlay`), 화면마다 따로 쓰는 것(`views`), 가격 그림(`chart`), 일정(`calendar`), 규제(`rules`), 품목 코드 조회(`cn`), 움직임(`motion`), 색 변형(`themes`).

## 게시하기 전에 거치는 것

1. 작성 실행의 자체 검사: 용어, 표기, 수치와 날짜.
2. 작성과 분리된 검증 실행이 원문을 다시 읽고 대조한다. 확인하지 못한 것은 통과시키지 않는다.
3. 게시 프로그램(`tools/publish/add_items`)이 제목, 요약, 실무 영향에 나온 수치와 날짜가 저장소의 원문 글에 있는지 한 번 더 본다. 원문 발췌는 원문에 그대로 있을 때만 싣는다.
4. 게시한 뒤에도 주마다 일부를 골라 지금의 원문과 다시 대조한다.

## 자료의 재이용

- EU 기관의 공식 자료는 출처를 밝히고 재이용합니다. `originals/`의 사본과 `collected/pages/`의 화면 글이 여기에 해당합니다.
