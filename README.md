# cbam-watch

EU 탄소국경조정제도(CBAM)의 규제 동향을 원문과 함께 정리해 보여 주는 사이트의 저장소입니다.

- 사이트: https://ansh91655-a.github.io/cbam-watch/
- 사이트의 정리와 번역은 자동으로 수집하고 작성한 것이며, 게시 전에 사람이 검수하지 않습니다. 정확한 내용은 반드시 원문에서 확인하세요. 법률 자문이 아닙니다.

## 폴더

| 폴더 | 내용 |
| --- | --- |
| `sources/registry.json` | 출처 대장. 어디를 어떤 방법으로 보는지 적혀 있다 |
| `collected/` | 수집 결과. `feed/`(그날 새로 보인 것), `state/`(이미 본 것의 열쇠), `pages/`(EU 공식 화면의 글), `status.json`(출처별 확인 결과), `archive/`(지난 소식을 한꺼번에 모은 것. 아래 '지난 소식 채우기' 참조) |
| `originals/` | EU 집행위원회 문서의 사본(`files/<문서 id>/<해시>/<원래 파일 이름>`), 뽑아 낸 본문(`text/`), 판 사이의 비교 결과(`diffs/`), 대장(`state.json`) `units/`에는 PDF에 적힌 짜임에서 읽은 뜻 단위(제목, 문단, 목록 항목, 표의 칸, 각주)를 둔다(`tools/pdfko/units.py`). |
| `assets/fonts/` | 국문 PDF에 번역을 찍는 글꼴(Pretendard. OFL 1.1이고 허락글이 함께 있다) |
| `data/` | 사이트에 게시한 데이터. 소식(`items.json`), 주제 목록(`topics.json`), 인증서 가격(`prices.json`, 프로그램이 가격표에서 만든다), 일정(`events.json`), 주간 요약(`digests.json`), 용어집(`terms.json`), 하나로 묶은 소식의 기록(`merged.json`), 규제별 진행 상황(`regulations.json`), 품목 코드 조회의 목록(`cn.json`), 법령에서 옮겨 온 참고 자료(`factor.json`, `duties.json`, `calc.json`, `calc-goods.json`), 규정 원문과 안내 문서의 국문 번역(`laws-ko/`, 문서마다 한 파일) |
| `reports/` | 보고 실행이 올리는 그날과 그 주의 보고 파일. 알림의 근거다 |
| `language/` | 국문 표기 기준(용어집 `glossary.json`), 번역 실행들이 정해 둔 낱말(`translation-terms.json`), 번역을 지운 까닭(`translation-reviews.json`), 검수의 결과(`translation-checks.json`) |
| `site/` | 공개 사이트의 화면 파일. 화면마다 모듈 하나(`js/views/`), 그림과 달력 같은 부품(`js/ui/`), 디자인 값(`css/tokens.css`)과 색 변형(`css/themes.css`), 파비콘과 공유 미리보기 그림과 라이선스 고지(`assets/`). 아래 '사이트의 디자인' 참조 |
| `console/` | 운영 화면의 파일. 올릴 폴더는 `python3 -m tools.publish.build_console`이 만든다(사이트의 화면 도우미 `dom.js`, `format.js`를 복사해 넣는다). 사이트 쪽 도우미가 바뀌어 콘솔의 모듈이 맞물리지 않게 되면 '도구 검사'가 잡는다(`tools/dev/modlink.mjs`) |
| `tools/` | 정해진 일을 하는 프로그램. 아래 표 참조 |
| `tests/` | 도구의 자동 시험. 도구나 시험, 시험이 읽는 화면의 셈과 참고 자료가 바뀌면 돈다(`.github/workflows/tests.yml`) |

### tools

| 묶음 | 하는 일 |
| --- | --- |
| `tools/common` | 웹에서 받기, HTML에서 글 뽑기, JSON 읽고 쓰기, 사이트 주소와 배포하는 곳 읽기(`siteinfo`: 주소는 `site/site.config.json`의 `url`, 사이트만 싣는 저장소를 따로 둘 때의 이름은 `deploy.json`의 `siteRepo`) |
| `tools/collect` | 출처 화면에서 새 항목 찾기(`extract`), JSON 목록 보기(`jsonwatch`), 그날 목록 만들기(`feed`), 실행(`run`). 이용 조건을 밝힌 공공기관 게시글의 본문 받기(`articles`: 수집 기록의 그 줄에 받은 글의 경로를 적어 예약 실행이 본문으로 요약하게 한다. 본문 자리 찾기는 `article_text`) |
| `tools/originals` | 문서 링크 찾기(`discover`), 받을 차례 정하기(`queue`), 판 남기기와 비교(`versions`, `diff`), 본문 뽑기(`textify`), 실행(`run`) |
| `tools/check` | 국문 글 검사: 용어(`term_check`, `term_lookup`), 표기(`style_check`), 수치와 날짜 대조(`fact_check`), 원문 발췌 확인(`excerpt_check`) |
| `tools/prices` | 인증서 가격표 읽기: 적용 기간 읽기(`periods`), 표의 행 읽기(`parse`), 가격 자료 만들기(`run`) |
| `tools/publish` | 게시 데이터에 더하기(`add_items`, `add_digest`), 요약 내리기(`withdraw`), 같은 일을 두 번 실은 소식을 하나로 묶기(`merge`: 묶인 소식은 `data/merged.json`에 남고, 옛 주소는 남긴 소식으로 넘어간다), 주제 목록(`topics`), 사이트와 운영 화면의 폴더 만들기(`build_site`, `build_console`). 사이트 폴더를 만들 때 규제 자료의 공개용 사본(`regulations`), 소식의 미리보기 그림 주소(`thumbs`), 구독 피드 `feed.xml`과 `rules.xml`(`feed`. 새 소식 받아 보기를 열어 둔 동안에만), 화면에서 바로 보는 문서 사본 `files/`(`derive`)도 함께 만든다. 규제 자료 고치기(`rule_edit`), 제목만 옮겨 실은 소식의 요약을 원문을 읽고 다시 쓴 것으로 바꾸기(`revise`)도 여기에 있다. 소식·의무 일정·용어집에 적힌 법령과 조문을 규정 원문으로 잇기(`crossrefs`), 부문별 모아 보기의 자료 만들기(`sectors`)도 사이트를 만들 때 함께 돈다 |
| `tools/notify` | 보고 파일에서 알릴 것을 골라 '운영 보고' 이슈에 적기(`reports`, `messages`, `github`, `run`) |
| `tools/run` | 예약 실행이 쓰는 보조 도구: 후보 고르기, 검증 대기 고르기, 보류된 초안 가운데 다시 쓸 것 고르기(`holds_to_fix`: 글을 고치면 풀리는 사유)와 그대로 다시 검증에 낼 것의 사본 만들기(`holds_to_recheck`: 원문을 열지 못한 것. 두 번까지, 규칙은 `rechecks.py`), 제목만 옮긴 초안의 원문 제목을 수집 기록에서 찾기(`feed_title`), 원문 발췌 자르기, 상태 점검(`health`, 규제 자료는 `rules_health`, 품목 코드 목록과 기관별 입장 비교표는 `cn_health`), 하루와 한 주의 요약, 보고 파일 만들기(`write_report`) |
| `tools/archive` | 공식 기록을 모으는 프로그램. 지난 소식을 한꺼번에 채울 때 손으로 돌리고, 규제 진행 상황에 쓰는 기록은 평일마다 자동으로 돈다: 출처별 모으기(`ecnews`, `newsletter`, `eurlex`, `cellar`, `docs`, `oeil`, `hys`, `presscorner`, `council`, `govuk`, `ukleg`, `fedreg`, `boards`)와 실행(`crawl`), 새 자료를 그날의 후보로 넘기기(`tofeed`), 화면의 짜임 살펴보기(`dump`), 싣기 전 검사(`gate`), 싣기(`publish`). 법령의 본문 받아 두기(`acts`: 부속서가 규칙의 글인 법령은 부속서까지 온전히), 법령의 앞선 판 남기기(`earlier`: 처음 관보에 실린 글과 지난 통합본. 달라진 곳 보기가 견줄 글) |
| `tools/cn` | 품목 코드 조회의 목록을 법령 원문에서 만드는 프로그램: 부속서의 품목 표 읽기(`annex`), `data/cn.json` 만들기(`build`), 통합본의 판 다루기(`versions`), 새 통합본이 나오면 본문을 받아 목록을 다시 만들기(`refresh`, 평일 수집이 돌린다. 부속서를 제대로 읽었는지의 확인에 걸리면 아무것도 바꾸지 않고 사유를 `collected/cn/refresh.json`에 남긴다). 원문은 `collected/archive/pages/eu-fulltext/`에 있다. 코드를 견주는 셈은 사이트의 `site/js/cn/match.js`, 개정안의 단계에 따라 안내의 말을 바꾸는 기준은 `site/js/cn/stage.js`에 있다 |
| `tools/thumbs` | 소식 카드의 미리보기 그림을 만드는 프로그램: 만들 것 고르기(`plan`), 원문 화면의 제목 부분 찍기(`shots.mjs`), 법령 PDF의 첫 장 받기(`pdfcover`), 줄여서 싣기(`finish`). 재이용이 허용된 공식 출처만 다루고, 화면을 여는 브라우저는 자동으로 여는 것임을 숨기지 않는다 |
| `tools/common` | 여러 프로그램이 함께 쓰는 것: 웹에서 받기(`net`), robots.txt 지키기(`robots`), 화면의 글 뽑기(`htmltext`), JSON 읽고 쓰기(`jsonio`), 사이트 주소와 배포 저장소(`siteinfo`) |
| `tools/laws` | 규정 원문 화면의 자료를 만드는 프로그램: 받아 둔 법령의 글을 조와 문단으로 나누기(`segment`), 안내 문서를 PDF의 뜻 단위에서 조각으로 만들기(`unit_segment`), 꼬리표가 없는 PDF의 글을 쪽·문단·절로 나누기(`pdf_pages`, `pdf_blocks`, `guide_segment`), 나누는 방식이 바뀐 문단에 옛 번역 옮겨 붙이기(`carry`), 싣는 문서의 목록(`catalog`, `guides`), 문서와 번역을 함께 읽기(`corpus`), 번역 자료 읽고 쓰기(`store`), 번역 검사(`check`, 용어는 `terms`), 전문용어의 영문 병기(`gloss`), 사이트 자료 만들기(`build`), 번역 실행마다 맡는 갈래(`plan`), 다음에 옮길 문단 고르기(`todo`)와 옮긴 것 넣기(`apply`, 끝맺음 맞추기는 `finish`), 번역 실행들이 정해 둔 낱말(`wording`), 검수(`verify`, 검수를 재려고 번역을 일부러 틀리게 바꾸는 `spoil`), 표본 검토(`review`), 모델 견주기 시험(`trial`), 진행 상황(`status`), 앞선 판과 견주기(`compare`)와 달라진 곳의 공개 자료(`revisions`), 같은 문장이 다르게 옮겨진 것 찾아 맞추기(`alike`). 아래 '규정 원문과 국문 번역' 참조 |
| `tools/pdfko` | PDF로 받은 문서를 다루는 프로그램: 낱말의 자리(`geometry`), 글자와 내용 조각 번호(`glyphs`), 구조 꼬리표(`tags`), 뜻 단위(`units`) 읽기와, 국문 PDF 만들기(단위를 글자에 잇기 `bind`, 자리 정하기 `layout`, 원문 글자 들어내기 `erase`, 글꼴 `fonts`, 찍기 `typeset`, 문서 하나 `build`, 사이트에 싣기 `site`). 꼬리표가 없는 PDF는 글을 맞추어 자리를 찾는다(`match`) |
| `tools/calc` | 인증서 비용 추정의 품목 자료를 법령의 표에서 만드는 프로그램: 받아 둔 표 읽기(`source`), 품목마다 기본값과 벤치마크를 짝지어 `data/calc-goods.json` 만들기(`build`) |
| `tools/sitecheck` | 만든 사이트를 브라우저로 열어 가로 넘침, 화면 오류, 접근성을 검사하는 프로그램(Node). 아래 '화면 점검' 참조 |
| `tools/art` | 사이트의 그림을 만드는 프로그램. 손으로 돌린다: 점 지도(`dotmap`, 나라 경계 읽기는 `world`), 아이콘(`icons`), 라이선스 고지(`notices`), 공유 미리보기 그림의 원본(`social.html`) |

자동으로 받는 것은 모두 `tools/common/net.py`를 거치고, 이 함수는 주소를 열기 전에 그 사이트의 robots.txt를 봅니다(`tools/common/robots.py`). 사이트가 자동 읽기를 막은 주소는 받지 않고, 막힌 주소는 `collected/robots.json`에 남아 그날의 상태 점검이 알립니다. 이 수집기의 이름(cbam-watch)을 적은 규칙과 함께 Claude의 수집기 이름을 적은 규칙도 따릅니다(받은 글을 Claude가 읽고 요약하기 때문입니다). 사이트가 확인 요청이나 접근 거부 화면을 내면 넘어서려 하지 않습니다. 주소 하나를 손으로 확인하려면 `python3 -m tools.common.robots <주소>`를 씁니다.

예약 실행(Claude)이 웹 화면을 직접 읽는 일은 최소로 둡니다. 예약 실행의 웹 읽기는 그 실행의 웹 검색 결과에 그대로 나온 주소만 사람의 확인 없이 열 수 있기 때문입니다(2026-11-12에 시험으로 확인. 저장소 파일이나 절차서에 적힌 주소, 열어 본 화면에 걸린 링크는 열리지 않습니다). 그래서 소식의 원문은 되도록 이 저장소의 자동 실행이 받아 둔 글에서 읽고(EU 기관의 화면과, 이용 조건을 밝힌 공공기관 게시글의 본문), 제목만 옮기는 소식은 수집 기록(`collected/feed/`)의 제목과 견주어 검증합니다. 출처 대장에서 `collector`가 `claude`인 출처만 예약 실행이 웹 읽기로 열며, 그 출처의 `find`에 적힌 검색어로 검색해 결과에 주소가 그대로 나올 때만 엽니다.

프로그램은 저장소 맨 위에서 `python3 -m tools.<묶음>.<이름>` 꼴로 돌립니다. 표준 라이브러리만 쓰고, PDF 본문을 뽑을 때만 `pdftotext`가 필요합니다. 시험은 `python3 -m unittest discover -s tests -t .`로 돌리고, 올리기 전에는 `sh tools/dev/check.sh`(자동 실행과 같은 꾸러미만 깐 깨끗한 환경에서 시험과 사이트 만들기)를 돌립니다. 자동 실행은 결과를 `sh tools/dev/push.sh`로 올립니다(올리기가 응답 없이 멈추면 끊고 세 번까지 다시 해 보고, 끝내 안 되면 그 실행이 실패로 남습니다).

## 규제별 진행 상황

사이트의 '규제' 화면은 `data/regulations.json` 하나로 그린다. 규제마다 지금의 단계, 현재 상황, 다음 단계, 연혁(사건마다 원문 주소)을 가진다.

- 연혁의 근거는 세 가지다. `stored`는 `collected/archive/`에 모아 둔 공식 기록과 맞는 사건이고 프로그램이 실제로 맞춰 본다. `web`은 자동으로 받을 수 없는 공식 화면을 읽고 확인한 사건, `press`는 언론 보도로만 아는 사건이다(화면에 '언론 보도'로 표시된다).
- 검사: `python -m tools.publish.regulations`(꼴, 높임말, 용어, 근거). 사이트를 만들 때는 꼴과 표기만 막고, 근거가 공식 기록과 달라진 것은 알리기만 한다(공식 기록은 날마다 바뀐다).
- 고치기: `python -m tools.publish.rule_edit`(연혁에 한 줄 더하기와 빼기, 단계와 설명 고치기, 새 규제 더하기). 고친 뒤 자료 전체를 검사하고, 걸리면 고치지 않는다.
- 기관별 입장 비교표: 규제에 `positions`가 있으면 화면에 '기관별 입장 비교'가 실린다(지금은 하류제품 확대 개정안과 임시 탈탄소화 기금 규정안). 칸마다 저장소에 받아 둔 원문 글에서 근거를 대고(`contains`, 그 문서에 없는 조항은 `lacks`) 프로그램이 맞춰 본다. `python -m tools.publish.rule_edit positions --id <규제> --file <표 파일>`로 넣고, 공개용 사본에는 칸의 글만 실린다.
- 분석 글: 규제에 `analysis`가 있으면 '무엇을 정하는 규제인가요' 아래에 배경, 주요 내용, 쟁점과 정세, 실무에서 볼 점이 실린다(검사와 변환은 `tools/publish/analysis.py`, 화면은 `site/js/views/rules/analysis.js`). 문단마다 근거 자료를 가리켜야 하고, 모아 둔 공식 자료만 가리키는 문단은 그 안의 날짜와 수를 자료의 글과 프로그램이 대조한다. 언론 보도에 기댄 문단은 글에서 그렇다고 밝혀야 한다. `python -m tools.publish.rule_edit analysis --id <규제> --file <분석 파일>`로 넣고 `analysis-show`로 꺼낸다. 규제의 단계나 연혁이 달라지면 화면이 '분석을 쓴 뒤에 달라졌다'고 스스로 밝히고, 사흘이 지나도록 그대로면 상태 점검이 알린다. 근거로 쓰는 글은 워크플로 '소급 수집'으로 받아 둔다. `steps`에 `eu-acts`를 적으면 시행 중인 법령의 본문을, `eu-fulltext`를 적으면 심의 중인 제안의 본문과 부속서, EU 배출권거래제 지침 통합본, 유럽의회 입법 관측소의 문서별 요약을, `uk-legislation`을 적으면 영국 CBAM 법령의 온전한 글을, `eur-lex-docs`를 적으면 CBAM 규정과 이어진 문서(계류 중인 소송의 공고 포함)를 받는다. `eu-tables`를 적으면 법령 부속서의 값 표를 칸의 자리를 살려 받는다(인증서 비용 추정의 자료). 규제를 고칠 때 다른 규제의 근거가 받아 둔 글과 달라진 것은 알리기만 하고 막지 않으며(`rule_edit.blocking`), 그 어긋남은 상태 점검이 따로 알린다.
- 달라진 것 찾기: `python -m tools.run.rules_watch`가 모아 둔 공식 기록이 지난번에 본 뒤로 달라졌는지 알려 준다. 본 것은 `data/rules-seen.json`에 적는다.
- 상태 점검: `tools/run/rules_health.py`가 근거 어긋남, 지난 일정, 반영되지 않은 변화, 기록 갱신 누락을 일일 보고의 문제로 올린다.
- 공식 기록을 읽지 못한 날: 사이트가 점검 중이거나 답이 끊겨도 모아 둔 목록은 줄어들지 않는다. 읽지 못한 것이 있는 실행은 앞의 목록에서 빠진 기록을 그대로 남기고(`tools/archive/store.py`의 `save_index`), EU 법령 데이터베이스의 연관 문서는 빠진 문서와 관계를 되살린다(`tools/archive/cellar.py`의 `restore`). 무엇을 읽지 못했는지는 `collected/archive/report/`에 남는다.

## 법령에서 옮겨 온 참고 자료

소식이나 규제의 연혁과 달리, 법령에 적힌 값을 그대로 옮겨 화면의 그림과 계산에 쓰는 자료가 있다. 모두 같은 틀을 따른다: 원본은 `data/`에 있고 항목마다 그 값이 적힌 법령 글(`collected/archive/pages/` 아래)을 가리키며, 검사 프로그램(`tools/publish/`)이 값과 대목을 그 글과 대조한다. 꼴이 깨지면 사이트 만들기가 멈추고, 받아 둔 글과 달라진 것('근거 어긋남')은 알리기만 한다. 공개용 사본에서는 저장소 안의 경로와 대조용 대목을 뺀다. 어긋남은 상태 점검(`tools/run/reference_health.py`)이 일일 보고의 문제로 올린다.

- CBAM 계수(`data/factor.json`, 검사 `python -m tools.publish.factor`): 현행 지침과 개정안의 해마다의 값. 규제 자료에 `figure: cbam-factor`가 적힌 규제의 화면에 그림으로 실리고(`site/js/ui/factorchart.js`), 인증서 비용 추정이 쓴다.
- 실무 달력(`data/duties.json`, 검사 `python -m tools.publish.duties`): 법령에 날짜가 적힌 EU CBAM과 영국 CBAM의 의무. 일정 화면의 '의무 일정'에 실리고 일정에도 합쳐진다(같은 일을 가리키는 게시 데이터의 일정은 의무 쪽을 남긴다).
  - 의무마다 누구의 일인지 적는다(`roles`: 신고인·수입자, 제3국 사업자, 검증기관, 영국 수입자). 화면에서 역할로 골라 보고, 고른 역할은 주소에 남는다(`#calendar-2027.role-verifier`, `site/js/calendar/roles.js`).
  - 해마다 돌아오는 의무에는 `yearly`를 적는다. 사이트를 만들 때 법령이 정한 날짜로 올해에서 두 해 뒤까지 펴서 싣고(`duties.expanded`), 뒤 해의 제목과 글이 달라야 하면 `yearly` 안에 적는다(`{prev}`는 그 전해).
  - 검증기관이 알아 둘 것은 `verifier`에, 생산자가 준비할 것은 `supplier`에 적는다. 값과 대목은 다른 참고 자료처럼 받아 둔 법령의 글과 대조한다.
- 인증서 비용 추정(`data/calc.json`과 `data/calc-goods.json`, 검사 `python -m tools.publish.calc`): 사이트의 '가격 > 비용 추정' 화면(`#calc`)이 쓴다.
  - `calc-goods.json`은 손으로 고치지 않는다. 받아 둔 법령의 표(`collected/archive/pages/eu-tables/`)에서 `python -m tools.calc.build`가 만든다: 무상할당 조정 이행규정 (EU) 2025/2620 부속서 5의 CBAM 벤치마크(품목 570개)와, 기본값 이행규정 (EU) 2025/2621 부속서 I(정정 규정 (EU) 2026/1740이 갈아 끼운 표)의 대한민국 표, 대한민국의 값이 없는 품목에 쓰는 '그 밖의 나라와 지역' 표. 법령이 정하지 않은 경우를 만나면 어림하지 않고 멈춘다.
  - `calc.json`은 손으로 적는 규칙이다: 마크업, 부문 간 보정계수, 벤치마크의 연도 구간, 생산경로의 이름, 계산식, 화면에 싣는 설명 글. 근거는 모아 둔 공식 기록(`collected/archive/`)이나 EU 집행위원회 문서에서 뽑은 본문(`originals/text/`)의 대목이다. 수식은 법령의 받아 둔 글에 그림으로만 있어, 식은 집행위원회 가이던스 4의 글과 대조하고 식의 항이 무엇인지는 법령의 글과 대조한다.
  - 셈은 `site/js/calc/compute.js`가 한다(시험은 `tests/test_calc.py`가 node로 돌린다). 정해지지 않아 가정한 값(2031년 이후의 벤치마크와 부문 간 보정계수)과 참고용인 값(2027년 수입분부터 갱신될 벤치마크)은 화면이 그렇다고 밝힌다.
  - 근거 법령을 고치거나 바로잡는 새 문서가 법령 데이터베이스 목록에 보이면 상태 점검이 알린다(`calc.json`의 `watch`). 그때는 `tools/archive/tables.py`의 대상을 새 법령으로 바꿔 표를 다시 받고(워크플로 '소급 수집', `steps`에 `eu-tables`), `python -m tools.calc.build`로 자료를 다시 만들어 달라진 것을 확인한 뒤, 반영한 문서를 `watch.known`에 적는다.
- 규제 화면에서 추정 화면으로 이어 주려면 규제 자료에 `tool: calc`를 적는다(`python -m tools.publish.rule_edit set --id <규제> --tool calc`).

## 규정 원문과 국문 번역

사이트의 '자료·안내 > 규정 원문'(`#laws`, `#law-<문서 id>.<조각>`)은 CBAM 규정(통합본)과 이행·위임규정의 원문을 국문 번역과 문단마다 나란히 보여 주고, 전체 규정에서 낱말이나 질문으로 조문을 찾게 한다. 규제 하나의 화면(`#rules-<규제>`) 오른쪽 칸에도 같은 찾기가 있다.

- 원문은 저장소에 받아 둔 EU 법령의 글이다(`collected/archive/pages/eu-fulltext/cbam-consolidated.txt`, `collected/archive/pages/eu-acts/`). 사이트 폴더를 만들 때 `tools/laws/build.py`가 조와 문단으로 나눠 `data/laws/`(목록 `index.json`, 법령마다의 본문, 검색에 쓰는 `search.json`)를 만든다. 싣는 법령과 차례는 `tools/laws/catalog.py`가 정한다.
- 번역은 `data/laws-ko/<법령 번호>.json`에 있다. 문단의 자리가 아니라 원문 문단의 글자에서 만든 열쇠에 붙는다. 그래서 통합본이 새로 나와도 글자가 그대로인 문단의 번역은 남고 바뀐 문단만 다시 옮기면 되며, 여러 법령에 똑같이 나오는 문단은 한 번만 옮긴다.
- 옮기는 차례: `python -m tools.laws.todo [--limit 글자 수] [--act 법령] [--titles]`가 다음 문단과 그 글에 나온 용어집의 낱말을 주고, 옮긴 것을 `{"blocks": {열쇠: 국문}}` 파일로 만들어 `python -m tools.laws.apply <파일>`에 넘긴다. 진행 상황은 `python -m tools.laws.status`.
- 검사에 걸린 문단: `apply`는 걸린 문단마다 걸린 횟수와 마지막 까닭을 번역 자료의 `held`에 적는다(번역이 들어가면 빠진다). 걸린 문단은 번역이 없어 줄의 맨 앞에 남으므로, 그런 문단이 쌓여 묶음을 채우면 번역이 나아가지 못한다. 그래서 `todo`는 세 번 걸린 문단을 다른 문단을 모두 옮긴 뒤로 돌리고(다음에 줄 때 앞의 까닭을 `remarks`에 함께 준다), 그때도 걸려 여섯 번이 되면 더 주지 않는다. 뒤로 돌린 문단의 수는 `status`의 전체 줄 끝에 나오고, 끝내 싣지 못한 문단은 실행 확인과 보고가 문제로 알린다(`tools/run/laws_health.py`). 웹 주소 안의 낱말은 옮길 말로도 용어집과 견줄 말로도 보지 않고, 주소와 번호만 있는 줄(주소 하나만 적은 각주)은 옮기지 않고 그대로 싣는다. 번역이 영문 그대로 둔 용어(화면에 적힌 이름)에는 국문 표기를 요구하지 않는다. 핵심 용어가 다른 뜻으로 쓰인 자리(installation of wind turbines의 '설치')는 `sources/translation.json`의 `senses`에 그 뜻의 표기를 적어 두면 막지 않고 알리기만 한다. 용어집이 쓰지 않기로 한 표기도 원문에 그 표기가 맞는 다른 낱말이 있으면(precision의 '정밀도') `senses`를 보고 알리기만 한다. 식과 화면에 뜨는 번호 붙은 알림 글(VAL748 …)은 원문대로 두어도 막지 않고, 원문의 각주 표시("[16]")는 번역에도 같은 수만큼 있어야 하고, 번역이 수를 갈라 적으면(2551 → 255[1]) 수가 빠진 것으로 막는다. 원문의 주소(https://…)가 번역에 그대로 있지 않아도 막는다(붙임표 하나만 빠져도 열리지 않는다). 걸린 문단은 `python3 -m tools.laws.held`로 보고(열쇠, 까닭, 원문), 까닭을 고친 뒤 `--reset`으로 걸린 횟수를 지우면 다음 묶음에 다시 나온다.
- 넣기 전의 검사(`tools/laws/check.py`): 원문의 수(날짜, 조 번호, 금액)가 번역에 모두 있는지, 부속서·장의 로마 숫자가 남아 있는지, 용어집이 쓰지 않기로 한 표기가 없는지, 원문에 핵심 용어(용어집의 `core`)가 나오면 번역에 그 국문 표기가 있는지를 본다. 걸린 문단은 넣지 않는다. 사람의 감수를 대신하는 검사는 아니다.
- 영문 병기: 번역 자료에는 국문만 두고, 사이트 자료를 만들 때 `tools/laws/gloss.py`가 핵심 용어에 영문을 괄호로 붙인다(조 하나에서 처음 나올 때 한 번, 원문 문단에 그 영문이 있을 때만). 용어집을 고치면 화면의 병기도 따라 바뀐다.
- 찾기(`site/js/laws/engine.js`): 질문에서 용어집의 낱말을 찾아 그 영문 표기로 원문을, 국문 표기로 번역과 조의 이름을 찾는다(번역이 없는 조문도 국문 질문으로 찾힌다). 문장을 지어 답하지 않고 낱말이 나온 조문의 위치만 알려 준다. 화면의 '찾은 낱말'에 어떤 영문 표기로 찾았는지 보인다.
- 번역은 비공식이다. 화면이 그렇다고 밝히고 EUR-Lex의 원문으로 이어 준다. 통합본은 EU가 참고용으로 내는 문서라는 것도 함께 밝힌다.
- 인용 복사(`site/js/laws/cite.js`): 문단 오른쪽의 표시나 조각 머리의 '인용 복사'를 누르면 원문, 국문, 출처(문서·조·PDF 쪽·판), 그 문단으로 바로 가는 주소(`#law-<문서>.<조각>.<문단 차례>`)가 함께 복사된다. 아직 옮기지 않은 문단은 국문 줄 없이 복사된다.
- 부속서: 부속서가 규칙의 글인 법령(산정 방법 (EU) 2025/2547, 검증 원칙 2025/2546, 인정 조건 2025/2551, 대륙붕·배타적 경제수역 2025/2210)은 부속서도 온전히 받아 싣는다(`tools/archive/acts.py`의 `WHOLE`). 값의 표인 부속서(기본값, 벤치마크)와 전환기간 규정의 부속서는 앞부분만 받아 두고, 화면이 그 부속서의 끝에 싣지 않은 줄 수와 원문 링크를 알린다(조각의 `cut`). 법령의 수식은 원문에 그림으로 실려 있어 번호만 남으므로, 그런 부속서의 머리에 원문에서 보라고 알린다(`formulas`).
- 달라진 곳 보기(`#changes-<문서>`): 문서의 앞선 판과 지금의 판을 문단 단위로 견줘 바뀐 곳, 더해진 곳, 빠진 곳을 원문과 국문으로 보여 준다.
  - 앞선 판: 법령은 처음 관보에 실린 글과 지난 통합본을 받아 남겨 둔다(`tools/archive/earlier.py`, `collected/archive/pages/eu-earlier/`. 새 통합본으로 갈아 끼울 때 그때까지 쓰던 글이 여기로 간다). 안내 문서는 원문 대장이 남겨 둔 지난 판을 쓴다.
  - 견주기는 `tools/laws/compare.py`가 한다: 번호가 같은 문단끼리 짝짓고, 각주 번호가 밀린 것과 따옴표·줄표의 꼴만 다른 것, 줄이 합쳐지거나 갈린 것은 같은 것으로 본다. 판의 차례와 공개 자료(`data/laws/changes/<문서>.json`)는 `tools/laws/revisions.py`가 만든다. 낱말 단위의 표시는 화면이 한다(`site/js/laws/worddiff.js`).
  - 앞선 판에만 있는 문단(바뀌기 전의 글, 빠진 글)도 국문으로 보이도록, 그런 문단만 담은 숨은 문서(`<문서>-was-<판의 날짜>`)를 번역과 검수의 줄에 세운다(`corpus.everything(history=True)`). 사이트의 목록과 검색, PDF에는 싣지 않는다. 번역 자료에서 쓰이지 않는 번역을 지울 때 이 문서가 쓰는 것은 남겨야 한다.
- 조문 잇기(`tools/publish/crossrefs.py`, `data/refs.json`): 소식의 글, 의무 일정의 근거, 용어집의 근거 조문에 적힌 법령과 조·부속서를 이 화면의 그 자리로 잇는다. 글에 법령(번호나 이름)과 그 바로 뒤의 조가 또렷이 적힌 곳만 잇고("CBAM 규정 제6조(1), 제22조(1)"), 법령 없이 적힌 조나 다른 법의 조문은 잇지 않는다. 조와 부속서의 끝에는 그 조가 근거인 의무 일정, 그 조를 적은 소식, 그 조에서 나온 용어를 접어서 보여 준다. 근거 칸에 적힌 조각이 사이트의 글에 없으면 상태 점검이 알린다(`tools/run/reference_health.py`).

### 안내 문서(가이던스, 등록부 안내서, 보고서)

같은 화면에 EU 집행위원회가 낸 문서도 싣는다. 무엇을 싣는지는 `sources/guides.json`이 정하고, 갈래(`group`)는 셋이다.

| 갈래 | 싣는 것 |
|---|---|
| `guide` 가이던스와 질의응답 | 가이던스 1~5f, 질의응답, 검증·인정 가이던스, 전력 질의응답, 제27a조(안) 질의응답 |
| `manual` 등록부 이용 안내서 | 사업자·검증기관 포털과 신고인 포털의 안내서, 접근 신청·권한 위임 절차, 한 장 요약, 개인정보 처리 고지 |
| `paper` 보고서와 안내 자료 | 이행규정 의견수렴 결과 요약, 개발도상국 안내, 전환기간에 쓰던 수입자 가이던스와 생산자 안내 자료 |

- 원문은 원문 대장이 받아 둔 PDF다. 문서가 새 판으로 바뀌면 그 판을 쓰고, 글자가 그대로인 문단의 번역은 남는다.
- 문단은 PDF에 적힌 짜임(구조 꼬리표)에서 읽는다. 집행위원회 PDF는 거의 모두 제목, 문단, 목록 항목, 표의 칸, 그림 제목, 각주가 무엇인지 파일 안에 적혀 있다. `tools/pdfko/units.py`가 이것을 뜻 단위로 읽어 `originals/units/`에 두고(수집 워크플로가 새 PDF를 받으면 만든다), `tools/laws/unit_segment.py`가 단위에서 조각을 만든다. 머리말·꼬리말과 쪽 번호, 차례는 싣지 않는다. 표의 칸은 줄과 칸의 자리를 함께 적어 화면이 표로 그리고(합쳐진 칸은 글의 가로 자리로 헤아린다), 본문에 붙은 각주 번호는 그 번호의 각주가 있을 때 `[3]`으로 적는다.
- 문단을 나누는 방식이 바뀌어 띄어쓰기나 글머리표만 달라진 문단에는 옛 번역을 옮겨 붙인다(`tools/laws/carry.py`). 글자와 숫자가 같을 때만 붙이고, 검사를 지나지 못하면 붙이지 않는다.
- 꼬리표가 없는 PDF(한 장 요약 1건)와 단위 파일이 없는 문서는 PDF에서 뽑은 글(`originals/text/`)을 줄 단위로 나눈다: `tools/laws/pdf_pages.py`가 되풀이되는 머리말·꼬리말, 쪽 번호와 차례 쪽, 쪽 아래의 각주를 가려내고(본문에 붙은 각주 번호는 `[3]`으로 바꾼다), `pdf_blocks.py`가 줄을 문단으로 묶고, `guide_segment.py`가 번호 붙은 제목마다 절로 나눈다. 표의 칸이나 본문의 수를 제목으로 잘못 보지 않도록 번호의 차례와 차례 쪽의 번호·제목을 함께 본다. 차례가 번호의 단과 제목의 단으로 나뉜 문서(등록부 안내서)는 둘을 차례대로 짝지어 쓴다. 제목 꼬리표가 없는 문서는 이 방식으로 찾은 제목을 빌려 쓴다. 단위 파일이 없는 PDF 문서는 실행 확인(`tools/run/laws_health.py`)이 알린다.
- 문서마다 제목을 찾는 방식을 정할 수 있다(`outline`). `auto`가 기본이고, `loose`는 차례가 없는 문서에서 "1. Introduction" 꼴의 제목까지 받으며, `none`은 제목을 찾지 않고 글 전체를 조각 하나(본문)로 둔다. 도안으로 된 한두 쪽짜리 자료는 글의 차례가 뒤섞여 뽑히므로 `none`으로 싣는다.
- 화면에 함께 보일 알림은 `remark`에 적는다(전환기간용 자료, 아직 채택되지 않은 조문, 도안으로 된 자료).
- 싣지 않는 것: 표 파일(xlsx)과 묶음 파일(zip), 기관의 이름과 연락처만 늘어놓은 문서, 새 판이 나와 지난 판이 된 문서. 까닭은 `sources/guides.json`의 `note`에 적는다.
- 화면은 문단의 꼴대로 그린다(`site/js/laws/blocks.js`): 목록 항목은 들여 쓰고, 표는 칸마다 원문과 국문을 위아래로 두며, 그림 안의 글자는 접어 둔다. 식과 그림은 원문 PDF에서 확인하라고 밝힌다.
- 원문과 번역을 PDF로 나란히 볼 수 있다(`#pdf-<문서>.p<쪽>`). `tools/pdfko`가 원문 PDF에서 번역이 있는 문단의 글자만 들어내고 같은 자리에 국문을 찍어 국문 PDF를 만든다. 쪽 수와 쪽의 크기가 같으므로 화면은 한 줄에 원문 쪽과 번역 쪽을 두어 함께 스크롤한다(PDF.js, `site/vendor/pdfjs`). 국문 PDF는 사이트를 만들 때 만들고(`tools/pdfko/site.py`), 입력이 같으면 만들어 둔 것을 쓴다(`.cache/pdfko`). 배포할 때 만들지 못한 문서는 지난 배포의 것을 그대로 싣고 목록(`data/laws/pdf.json`)에 그렇게 적으며, 상태 점검이 알린다. 도안으로 된 자료(`sources/guides.json`에 `"side": false`로 적은 문서)는 나란히 보기에 싣지 않는다: 그림으로 박힌 제목 위에 번역이 겹치고 기관의 표장이 남아, 번역본이 공식 문서처럼 보이지 않아야 한다는 조건을 채우지 못한다.
  - 쪽마다 비공식 번역임을 적고 첫 쪽에는 띠로 알린다. 꼬리표에 기관의 표장이라고 적힌 그림은 가린다(도안으로 그려진 표장은 가리지 못한다). 번호와 글머리표, 각주 번호, 번역하지 않는 글(수식, 쪽 번호, 머리말·꼬리말)은 원문 것이 그대로 남는다. 차례 쪽에는 번호가 같은 조각의 제목 번역을 앉히고 점줄과 쪽 번호는 둔다.
  - 번역이 원문보다 길면 아래 빈 곳을 쓰거나 글자를 줄인다(0.6배까지). 그래도 자리가 모자라거나 줄들이 문단 꼴이 아니면 그 문단은 원문 그대로 둔다. 글꼴은 `assets/fonts`의 Pretendard다(OFL 1.1). 원문이 굵은 글씨인 곳만 굵게 찍는다.
- 찾기에 쓰는 글은 법령의 것(`data/laws/search.json`)과 따로 둔다(`search-guides.json`). 크기가 커서 규정 원문 화면에서 찾을 때만 받는다.

### 번역을 하는 실행

- 번역은 예약 실행이 한다. 실행마다 무엇을 얼마나 옮기는지는 `sources/translation.json`이 정한다(`python -m tools.laws.todo --runner <이름>`). 갈래를 다른 실행으로 옮길 때는 그 파일만 고친다.
- 실행은 앞의 실행을 기억하지 못한다. 용어집에 없는 전문용어를 어떻게 옮겼는지는 `language/translation-terms.json`에 적어 두고(`tools.laws.wording`), 다음 묶음을 받을 때 그 글에 나온 낱말이 함께 나온다. 확인된 표기가 아니므로 운영자가 살펴 용어집으로 옮긴다.
- 모델이나 방법을 견줄 때는 `trials/request.json`으로 시험을 청한다(`tools.laws.trial`). 이미 실린 번역을 보여 주지 않고 같은 문단을 다시 옮기게 해서 두 번역을 견준다. 시험의 번역은 `trials/`에만 쌓이고 사이트에는 실리지 않는다.
- 넣을 때 용어집 낱말의 띄어쓰기를 권장 표기로 맞추고(`tools.laws.terms.unify`), 문장의 끝맺음을 한 가지 꼴로 맞춘다(`tools.laws.finish`: "…다"로 끝나면 마침표). 번역하는 쪽이 달라져도 화면의 영문 병기와 찾기가 같은 글자로 걸리고, 문단의 끝이 들쭉날쭉하지 않게 하려는 것이다.

- 번역과 검수는 서로 다른 예약 작업이 한다. 번역한 모델과 다른 모델이 읽게 하려는 것이다. 실행 하나가 읽고 쓸 수 있는 양에는 한도가 있어, 번역 실행의 몫은 번역 네 묶음이고 검수 실행의 몫은 검수 네 묶음이다(`sources/translation.json`). 더 빨리 하려면 몫을 늘리지 않고 실행을 더 자주 돌린다. 예약 작업 하나는 한 시간에 한 번까지만 돌 수 있으므로 같은 절차서를 따르는 예약 작업을 시각을 엇갈려 여럿 둔다. 실행들이 겹치지 않게, 실행은 시작할 때 `python3 -m tools.laws.lock take <실행 id> --work translate`(검수는 `--work verify`)로 차례를 잡고 끝날 때 `release`로 푼다. 자물쇠는 main에 올리는 파일 하나(`locks/translating.json`)이고, 먼저 올린 쪽만 잡는다. 이 파일은 어느 자동 실행의 경로에도 들지 않아 자물쇠만 바뀐 커밋은 검사나 배포를 돌리지 않는다. 잡은 채로 멈춘 실행의 자물쇠는 12분이 지나면 다음 실행이 걷어 낸다. 자기 일(옮길 문단이나 검수할 문단)이 없으면 실행은 차례를 잡지 않고 끝낸다(`take`가 3으로 끝난다). 번역이 다 끝난 뒤의 실행이 빈 커밋을 남기지 않게 하려는 것이다.
- 번역은 묶음마다 저장소에 올라오지만 사이트는 실행이 끝날 때 한 번만 다시 실린다. 실행이 차례를 풀 때 지난번에 실은 뒤로 올라온 번역이 있으면 `stamps/translated.json`을 고쳐 함께 올리고, 사이트 배포와 화면 점검은 번역 파일(`data/laws-ko`)이 아니라 이 파일이 바뀔 때 돈다. 여러 실행이 묶음마다 배포를 돌리면 한 시간에 스무 번쯤이 되어 GitHub Pages가 권하는 횟수(한 시간에 열 번)를 넘기 때문이다. 틀려서 지운 번역(`language/translation-reviews.json`이 바뀜)은 기다리지 않고 바로 실린다. 번역 파일의 꼴을 보는 자동 시험(도구 검사)은 묶음마다 그대로 돈다.

### 번역의 검수

번역은 기계 검사만 거쳐 실린다. 검사는 수와 용어는 잡지만 뜻이 틀린 문장이나 빠진 말은 잡지 못한다. 그래서 세 겹으로 본다.

1. **모든 번역을 다른 모델의 실행이 원문과 견줘 읽는다**(`tools.laws.verify`). 번역 검수 실행이 번역 실행들이 옮겨 둔 문단을 읽는다(`verify todo`). 틀린 번역은 지우고 까닭을 적으며(`verify apply`가 `review.drop`을 부른다), 틀리지 않은 번역은 검수를 마친 것으로 적는다(번역 자료의 `checked`). 번역이 바뀐 문단은 `checked`에서 빠져 다시 읽힌다.
2. **검수가 제대로 읽는지 잰다.** 묶음마다 번역 몇 개를 일부러 틀리게 바꿔 섞어 넣는다(`tools.laws.spoil`: 의무와 허용, 포함과 제외 같은 말 뒤집기, 부정 빼기, 문장 빼기). 어느 것이 바꾼 것인지는 묶음에 적지 않는다. 바꾼 것을 잡아낸 비율이 문턱(`sources/translation.json`의 `verify.catch`)보다 낮으면 그 묶음의 검수는 버린다. 바꾼 번역은 작업 파일(`.work/`)에만 있고 번역 자료나 사이트에는 들어가지 않는다.
3. **주마다 표본을 다시 읽는다**(주간 작업, `python -m tools.laws.review sample`). 날마다의 검수가 지나친 것을 한 번 더 걸러 내려는 것이다. 앞선 판에만 있는 문단의 번역도 표본에 든다.

- 지워진 문단은 번역하는 실행이 까닭과 함께 다시 받는다(`todo`의 `remarks`, `language/translation-reviews.json`). 같은 문단을 두 번 지우고도 또 틀렸다고 하면 지우지 않고 '가리지 못한 문단'으로 적어 둔다(`language/translation-checks.json`의 `disputed`). 사람이 볼 것이다.
- 한 묶음에서 틀렸다고 한 비율이 지나치게 높으면(`verify.harsh`) 반영하지 않고 알린다.
- 날마다의 결과(읽은 묶음, 틀리지 않다고 본 문단, 지운 문단, 바꿔 섞은 번역과 잡아낸 수)는 `language/translation-checks.json`에 쌓인다. `python -m tools.laws.verify status`가 한 줄로 간추린다.
- 같은 문장은 같은 번역으로(`tools/laws/alike.py`): 여러 문서에 되풀이되는 같은 문장(가이던스마다 붙은 정의 목록, 법령을 옮겨 적은 문장)이 앞의 번호나 각주 번호, 끝의 문장부호만 달라 따로 옮겨지면 문서마다 조금씩 다르게 읽힌다. 이 도구가 그런 묶음을 찾아, 법령의 번역(없으면 가장 많이 쓰인 번역)을 바탕으로 나머지를 맞춘 글을 만든다. 문단의 번호와 각주 번호, 끝의 문장부호는 그 문단의 것을 지킨다. 묶음마다 검토해 골라 둔 바탕은 `language/alike-picks.json`에 있고 그것이 먼저다. `python -m tools.laws.alike --write <파일>`로 만든 파일을 `tools.laws.apply`로 넣으며, 바뀐 문단은 검수 표시가 지워져 다시 읽힌다. 남은 묶음의 수는 `python -m tools.laws.status`가 알린다.
- 상태 점검(`tools/run/laws_health.py`)은 싣기로 한 문서를 원문 대장에서 찾지 못한 것, 절 나누기가 문서의 차례와 어긋난 것, 번역이 남았는데 여러 날 늘지 않은 것, 검수가 여러 날 늘지 않거나 일부러 바꾼 번역을 놓친 것, 번역과 검수가 맞선 문단이 생긴 것을 알린다.

## 부문별 모아 보기

사이트의 '자료·안내 > 부문별 보기'(`#sector-<부문>`: steel, aluminium, cement, fertilisers, hydrogen, electricity)는 부문 하나에 관한 것을 한 화면에 모은다: 대상 품목(CN 코드, 온실가스, 산정 범위), 그 부문의 EU 집행위원회 문서와 큰 절, 기본값·벤치마크가 정해진 품목 수와 마크업, 다가오는 의무 일정, 그 부문의 소식, 모든 부문에 함께 적용되는 문서.

- 무엇을 모을지는 `sources/sectors.json`이 정한다(부문마다 품목 목록의 부문 이름, 비용 추정 자료의 부문 이름, 문서의 id, 소식을 고르는 낱말). 사실을 적는 글은 이 파일에 두지 않는다.
- 화면의 수와 글은 모두 사이트의 다른 자료에서 만든다(`tools/publish/sectors.py` → `data/sectors.json`): 품목과 온실가스, 산정 범위는 품목 코드 조회의 목록(`cn.json`), 품목 수와 마크업은 인증서 비용 추정의 자료(`calc.json`), 문서의 이름과 차례는 규정 원문의 목록(`laws/index.json`), 소식은 제목·요약·다룬 내용에 그 부문의 낱말이 나온 것. 글로 풀어 쓰는 일은 `site/js/sector/facts.js`가 한다.
- 자료가 가리키는 부문이나 문서가 사이트의 자료에 없으면 사이트 만들기가 멈춘다(문서의 id가 바뀌었을 때 잡힌다).

## 사이트 검색과 주 메뉴의 펼침 목록

머리글의 검색 칸에 찾는 말을 적으면 검색 화면(`#search-<찾는 말>`)이 소식, 규제, 규정 원문, 용어집, 일정, 품목 코드, 원문 대장에서 한 번에 찾아 갈래별로 보여 준다. `/` 키를 누르면 검색 칸으로 간다. 좁은 화면에서는 칸 대신 돋보기 단추가 검색 화면을 연다.

- 낱말을 읽고 점수를 매기는 일은 규정 원문의 찾기 엔진(`site/js/laws/engine.js`)이 한다. 그래서 용어집의 낱말은 국문으로 적어도 영문 표기까지 함께 찾는다(예: '기본값'으로 'default value'가 든 문서 이름과 조문).
- 게시 데이터의 기록을 찾기 좋은 줄로 바꾸는 일은 `site/js/search/rows.js`, 갈래마다 찾고 걸러 내는 일은 `find.js`, 화면으로 바로 가는 길은 `pages.js`, 품목 코드 읽기는 `codes.js`가 한다. 모두 화면 요소를 다루지 않아 node로 시험한다(`tests/test_search.py`). 화면은 `site/js/views/search.js`와 `views/search/`, 머리글의 칸은 `site/js/ui/sitesearch.js`다.
- 낱말이 여럿이면 함께 나온 곳만 보여 준다(둘까지는 모두, 셋부터는 하나가 빠져도 된다). 그런 곳이 어디에도 없을 때에만 낱말의 일부가 나온 곳으로 물러서고, 화면이 그렇다고 밝힌다.
- 찾는 말이 CN 코드이면(예: `7208`, `CN 7318 15`) 품목 코드 조회와 같은 셈으로 가린 판정을 맨 위에 보여 주고, 글에서는 그 코드를 낱말 하나로 찾는다(붙여 쓴 꼴과 띄어 쓴 꼴). 목록에 없는 네 자리 숫자는 연도일 수 있어 코드로 보지 않는다.
- 짧은 영문 낱말과 숫자는 다른 낱말 속에 든 것을 찾은 것으로 보지 않는다. 세 글자까지의 약어(ETS, CEM)는 낱말 하나로 나온 곳만(markets, cement에 걸리지 않게), 그 밖의 세 글자까지의 낱말은 낱말의 첫머리에서만, 숫자는 그 숫자 하나로 나온 곳만 찾는다. 두 글자 약어와 흔한 낱말과 글자가 같은 약어(SEE, BAT)는 대문자로 적었을 때만 약어로 읽고, 질문에서 용어집의 영문 표기를 읽을 때에도 낱말의 첫머리부터 맞아야 한다(neutral의 eu를 EU로 읽지 않는다). 규정 원문의 찾기에도 같은 기준이 쓰인다.
- 결과를 누르면 그 자리로 간다: 용어집과 원문 대장은 그 말로 걸러 보여 주고(`#terms-<말>`, `#docs-<말>`), 일정은 그 일정으로 옮겨 가 잠깐 표시한다(`#calendar-<해>.<일정의 번호>`). 소식의 출처 이름은 찾는 글에도 결과에도 넣지 않는다.
- 규정 원문의 글은 크므로 다른 갈래를 먼저 보여 주고 나서 읽어 더한다.

주 메뉴에 마우스를 올리면 그 메뉴 아래의 목록이 펼쳐진다(소식의 주제, 규제의 묶음, 가격과 자료·안내의 화면, 일정이 있는 해). 마우스가 없는 기기와 자판을 위해 메뉴 옆에 펼침 단추가 있고, 메뉴에서 아래 화살표 키를 눌러도 펼쳐진다. 메뉴가 둘째 줄로 내려가는 좁은 화면에서는 쓰지 않는다.

- 목록의 내용은 게시 데이터를 따른다. 주제는 `data/topics.json`, 규제 묶음과 일정이 있는 해, 소식이 있는 주제는 사이트 폴더를 만들 때 `site.json`의 `menu`에 실린다(`tools/publish/derive.py`의 `menu`). 화면이 처음 뜰 때 읽는 파일에 실어, 메뉴를 그리려고 큰 자료를 따로 읽지 않는다.
- 화면은 `site/js/ui/navmenu.js`와 `site/css/navmenu.css`, 펼침 단추는 `site/index.html`에 있다. 단추마다 목록이 있는지는 `tests/test_search.py`가 본다.

## 화면 점검

`tools/sitecheck`는 만든 사이트를 브라우저(이미 깔려 있는 크롬)로 열어 검사한다. 화면 파일이나 게시 데이터가 바뀌면 워크플로 '화면 점검'(`.github/workflows/sitecheck.yml`)이 돌린다. 사이트 배포는 이 검사를 기다리지 않고, 문제가 나오면 '운영 보고' 이슈에 어느 화면이 왜 걸렸는지 적힌다(`python -m tools.notify.run --event sitecheck`).

- `layout`: 모든 화면을 다섯 너비(360~1440)로, 규제 화면을 규제마다 세 너비로 열어 가로 넘침, 화면 밖으로 나간 글, 그려지지 않은 화면, 본문에 찍힌 깨진 값(undefined, NaN), 화면 오류와 받지 못한 파일을 본다.
- `axe`: 주요 화면에 접근성 자동 검사(axe-core)를 색 변형 셋, 너비 둘로 돌린다.
- `calc`: 인증서 비용 추정 화면을 실제로 다뤄 본다(품목 찾기와 고르기, 신고 방법과 연도 바꾸기, 초점이 제자리로 가는지, 결과에 깨진 값이 없는지).
- 화면의 목록은 만든 사이트의 데이터에서 뽑으므로(`plan.mjs`) 규제나 주제가 늘어도 따라간다.
- 손으로 돌리기: `python3 -m tools.publish.build_site /tmp/_site && npm ci --prefix tools/sitecheck && node tools/sitecheck/run.mjs /tmp/_site` (일부만 돌리려면 `--only layout,axe,calc`, 결과 파일은 `--report <파일>`). 크롬이 다른 곳에 있으면 `CHROME_PATH`에 적는다.
- 고친 화면을 눈으로 볼 때는 `node tools/dev/shot.mjs <사이트 폴더> "<#화면>@<너비>[:<높이>]=<그림 파일>[!<누를 요소>]"`로 그림을 찍는다(가로 넘침과 화면 오류도 함께 알려 준다).

## 지난 소식 채우기

사이트를 연 날보다 앞선 소식(2025년 1월부터)은 평소의 자동 실행과 따로 한 번에 채웠습니다. 같은 일을 다시 할 때의 차례입니다.

1. 모으기. 워크플로 '소급 수집'(`.github/workflows/archive.yml`)을 손으로 돌립니다. `mode`를 `crawl`로 두고 `steps`에 출처 이름을 띄어 적으면 그 출처만 돕니다(비우면 모두). 결과는 `collected/archive/`에 쌓입니다. 출처마다 목록(`<출처>.json`), 재이용이 허용된 자료의 원문 글(`pages/`), 실행 결과(`report/`)가 있습니다.
   - `ec-news`: EU 집행위원회 조세·관세총국 소식. 사이트 지도에서 소식 주소를 얻어 본문에 CBAM이 나오는 것만 남깁니다.
   - `ec-newsletter`: EU 집행위원회가 보내는 CBAM Newsletter의 보관함. `eur-lex`: CBAM 법령의 제목, 채택일, 관보 게재일, 시행과 적용에 관한 조문(EU 출판국의 자료 창구에서 받습니다).
   - `ep-oeil`: 유럽의회 입법 관측소의 절차 기록. `ec-hys`: 의견수렴 목록. `uk-govuk`: 영국 정부 CBAM 문서의 변경 기록.
   - `kr-boards`: 국내 기관 게시판의 제목, 날짜, 주소. 본문은 받아 두지 않습니다(산업통상부 보도자료만 부제와 첫 문단을 짧게 남깁니다).
2. 쓰기. 모아 둔 글을 읽고 국문 초안을 만듭니다. 초안 파일은 저장소에 올리지 않습니다.
3. 싣기. `python3 -m tools.archive.publish --drafts <초안 파일> [--dry-run]`. 형식, 문체, 용어, 원문 대조(수치와 날짜, 게시일), 링크, 원문 발췌를 검사해 통과한 것만 `data/items.json`에 더하고 `backfill` 표시를 붙입니다. 이 표시가 있는 소식은 원문이 그 주에 나온 것이 아니면 주간 요약의 대상에서 빠지고(`tools/run/week_items.py`), 주간 작업이 주마다 10건씩 원문과 다시 대조합니다.

제목만 옮겨 실은 소식. 국내 기관 게시판의 지난 글은 본문을 받아 두지 않아 제목만으로 한 문장을 썼습니다. 이런 소식에는 `brief` 표시가 있고 사이트에서 요약 없이 한 줄로 보입니다. 소식의 기본 목록과 건수, 최신 동향에서는 빼고 '국내 공지·자료'(`#news-notices`)에 달마다 모아 보여 줍니다(`site/js/news/notices.js`). 원문을 읽고 요약을 쓴 뒤 `python3 -m tools.publish.revise`로 바꾸면(문체, 용어, 길이, 수치와 날짜를 검사합니다) 표시가 떨어지고 카드로 보입니다. 쓰는 법은 그 파일 머리에 있습니다.

## 사이트의 디자인

- 방향: 짙은 남색의 큰 머리(점 지도, 지금 알아 둘 수치 세 칸)와 밝은 본문입니다. 본문의 칸은 모서리가 둥근 카드에 옅은 그림자를 두고, 단추는 알약 모양입니다. 값은 모두 `site/css/tokens.css`에 있습니다.
- 색은 EU 깃발의 파랑(#003399)과 노랑(#FFCC00)을 빌렸습니다. 깃발(별 열두 개)과 EU 기관의 로고는 쓰지 않습니다. 개인이 운영하는 비공식 사이트입니다.
- 글꼴은 Pretendard 하나입니다.
- 이름표는 글자입니다: 'CBAM' 뒤에 노란 세로선(국경선)과 '규제동향'. 네모난 표지(`site/assets/favicon.svg`, CB와 AM 사이에 노란 선)는 탭 아이콘에만 씁니다.
- 첫 화면(`site/js/views/home.js`가 `home/` 폴더의 칸들을 차례로 놓습니다): 큰 머리(`hero`, `facts`. 수치 칸 위에 새 소식 한 줄), 가장 최근의 요약(`digest`. 기간에 따라 '이번 주 요약', '지난주 요약', '주간 요약'으로 부르고, 여러 주를 묶은 요약은 '최근 동향 요약'이라고 부릅니다), 가장 중요한 소식(`feature`), 다가오는 일정·인증서 가격 추세·주제별 소식·규제 진행 상황(`panels`), 품목 코드 조회(`lookup`), 최근 소식, 품목별 가이던스(`sectors`).
- 점 지도(`site/js/ui/heromap.js`)는 두 장을 겹친 것입니다. 아래 장은 유라시아를 점으로 찍은 지도(EU 회원국은 밝게, 한국은 노랗게)이고, 위 장은 한국에서 EU의 항구 다섯 곳으로 가는 선입니다. 선은 화면이 열릴 때 한국에서 EU 쪽으로 한 번 그려지고, 그 뒤로는 작은 빛이 같은 쪽으로 천천히 지나갑니다(움직임을 줄이도록 설정한 기기에서는 멈춘 그림). 선은 실제 뱃길이 아니라 방향을 나타낸 그림입니다. 지도 위와 아래에는 이름이나 설명글을 두지 않습니다(무엇을 그린 것인지는 화면 낭독기용 글에만 적혀 있습니다).
- 움직임은 `site/css/motion.css`와 `site/js/ui/motion.js`에 모아 두었습니다. 본문의 칸은 화면에 들어올 때 한 번 차례로 올라오고, 가격 그림의 선과 규제 단계의 선은 그때 그려지며, 큰 수치는 올라갑니다(`ui/countup.js`). 지금 진행 중인 것(갱신 시각, 진행 중인 규제, 지금 가격, 일정선의 오늘)은 점이 천천히 번집니다. 첫 화면의 큰 머리에는 가장 최근 소식의 제목이 한 줄씩 돌아가고(`ui/ticker.js`), 품목 코드 조회 칸의 예시가 번갈아 바뀌며(`ui/typehint.js`), 주 메뉴의 밑줄은 메뉴 사이를 미끄러져 옮겨 갑니다(`ui/navink.js`). 긴 글 화면(규제 하나)에서는 머리글 아래에 읽은 만큼 선이 차고, 한참 내려오면 맨 위로 가는 단추가 보입니다(`ui/scrollcue.js`). 움직임을 줄이도록 설정한 기기에서는 모두 멈추고 아무것도 숨기지 않습니다. 새로 만든 칸이 화면에 들어올 때 나타나게 하려면 `ui/motion.js`의 목록에 그 칸의 이름을 더합니다.
- 소식의 제목이나 미리보기 그림을 누르면 원문으로 가기 전에 국문 요약 화면(`#item-<소식 번호>`, `site/js/views/item.js`)을 먼저 보여 줍니다. 제목이 곧 내용인 한 줄 소식만 원문으로 바로 갑니다(`site/js/ui/itemlink.js`). 뒤로 가면 보던 자리로 돌아옵니다(`site/js/router.js`).
- 닫아 둔 기능: 새 소식 받아 보기(구독 피드와 안내 창, `site/js/ui/subscribe.js`, `tools/publish/feed.py`)와 의견 보내기(`site/js/ui/feedback.js`)는 만들어 두었지만 지금은 닫혀 있습니다. `site/site.config.json`의 `features`에서 `subscribe`, `feedback`을 `true`로 바꾸면 다시 열립니다. 닫혀 있는 동안에는 화면에 단추가 없고 구독 피드 파일(`feed.xml`, `rules.xml`)도 만들지 않습니다.
- 색 변형은 세 가지입니다: 네이비(기본), 화이트, 미드나잇. 주소에 `?theme=white`처럼 붙이면 바꿔 볼 수 있고, 기본값은 `site/js/theme.js`의 `DEFAULT`입니다. 변형마다 달라지는 값은 `site/css/themes.css`에만 있습니다.
- CSS는 쓰임새로 나눴습니다: 값(`tokens`), 바탕(`base`), 틀과 큰 머리와 지도(`layout`), 여러 화면이 함께 쓰는 부품(`components`), 첫 화면(`home`), 소식 요약 화면(`item`), 뜨는 창과 여백의 탭(`overlay`), 화면마다 따로 쓰는 것(`views`), 가격 그림(`chart`), 일정(`calendar`), 규제(`rules`), 품목 코드 조회(`cn`), 움직임(`motion`), 색 변형(`themes`).
- 그림은 사진 없이 직접 만든 것과 자유롭게 쓸 수 있는 것만 씁니다.

## 게시하기 전에 거치는 것

1. 작성 실행의 자체 검사: 용어, 표기, 수치와 날짜.
2. 작성과 분리된 검증 실행이 원문을 다시 읽고 대조한다. 확인하지 못한 것은 통과시키지 않는다.
3. 게시 프로그램(`tools/publish/add_items`)이 제목, 요약, 실무 영향에 나온 수치와 날짜가 저장소의 원문 글에 있는지 한 번 더 본다. 원문 발췌는 원문에 그대로 있을 때만 싣는다.
4. 게시한 뒤에도 주마다 일부를 골라 지금의 원문과 다시 대조한다.

## 자료의 재이용

- EU 기관의 공식 자료는 출처를 밝히고 재이용합니다. `originals/`의 사본과 `collected/pages/`의 화면 글이 여기에 해당합니다.
- 공공기관 자료는 짧게 요약하고, 민간 기업과 협회와 유료 매체의 자료는 제목이 알려 주는 사실과 링크만 다룹니다. 본문을 저장하지 않습니다.
- 다만 화면이 이용 조건을 스스로 밝힌 공공기관 게시글은 본문을 받아 둡니다(`collected/pages/items/`). 2026-11-12에 기관마다 확인한 대상은 산업통상부 보도·참고자료(공공누리 1유형), 네덜란드 배출권청(CC0), 영국 GOV.UK(Open Government Licence v3.0), 법무부(글마다의 칸이 공공누리 1유형일 때만)입니다. 받은 화면이나 그 기관의 저작권 안내 화면에 그 글귀가 있을 때만 저장하고, 저장한 글의 머리에 주소, 출처, 화면에 적힌 이용 조건을 적습니다. 게시글 머리의 담당자 이름과 전화번호는 싣지 않습니다. 대상 출처와 확인할 글귀, 받지 않기로 한 기관과 그 까닭은 출처 대장의 `articles`와 `ops`에 있습니다. 새 출처를 넣기 전에는 워크플로 '본문 받기 시험'으로 그 화면이 어떻게 읽히는지 봅니다(`tools/collect/articles_try.py`).
- 규정 원문 화면은 EU 법령의 글(출처 EUR-Lex)과 EU 집행위원회 안내 문서의 글(출처 집행위원회 조세·관세총국)을 문단마다 싣고 국문 번역을 붙입니다. 번역은 이 사이트가 옮긴 비공식 번역입니다.
- 소식 카드의 미리보기 그림은 EU 기관과 영국 정부(Open Government Licence v3.0)의 자료만 줄여 싣습니다. 재이용 조건을 확인하지 못한 출처의 화면은 그림으로 만들지 않습니다.
- 원문의 저작권과 재이용 조건은 각 출처를 따릅니다.
